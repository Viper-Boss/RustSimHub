# PM8916 PON 诊断源码审查稿

基于用户在2026-10-23会话中提供的 `pon_dump.c`，保留其 GPL-2.0 标识。该目录独立于固件组成和所有自动加载/启动单元。没有设备操作脚本，也没有自动安装目标。

这是用于离线编译和后续审查的实验源码，**不是已验证可加载的修复**。它不解决关机变重启，也不修改 PMIC 控制寄存器。`regmap_read` 没有写操作，并不自动证明所有读取都无硬件副作用。

与所提供版本相比：

- 在取得平台设备引用之前，先处理 `reg` 读取失败，避免该错误路径泄漏 `pdev` 引用。
- 拒绝禁用节点和超出16位SPMI地址范围的基址；缺失父设备/regmap时释放引用并返回错误。
- 省去缺少实际读取依据的 `0x0e`。其余偏移也仍待核实实际PMIC代次与读取副作用。
- 记录第一次读取错误，并在结束释放引用后返回该错误。部分/全部读取失败不会以模块初始化成功掩盖；失败前已输出的日志可能仍存在。
- 注释明确没有开机集成，不声称设备引用等价于 regmap 生命周期保护。

仍未解决的验收条件：真实PM8916寄存器语义、并发解绑时的regmap生命周期、实际读取结果、早期启动时机、持久日志落盘和对应boot的证据。即使真实内核编译、版本和导出核对通过，也不能据此标为硬件安全或恢复了关机测试授权。

内核外部模块的构建需要固定源码、准确配置、生成头、匹配导出及工具链；本项目的实际检查和制品摘要另见 `docs/VALIDATION-PON-DUMP-REVIEW-P6Z.md`。不能仅使用桩头文件语法检查替代真实构建。当前文件不提供 `insmod` 或开机自动加载步骤。
