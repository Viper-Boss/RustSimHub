# 收尾实测清单（交给测试的人照着做）

这份清单只列需要人动手的测试。每项写明：前提、步骤、怎样算通过、失败时要带回来的信息。
做完把“结果记录”一节填好发回即可。**不要为了让测试通过去改设备上的文件或配置。**

通用约定：

- 设备页面：`https://192.168.120.167:8443`，用已经登录过的那个 Chrome 打开。登录页点“这个浏览器已获授权，直接登录”。
- **不要清除这个站点的浏览器数据**，所有者钥匙只在这里，丢了无法找回。
- 不要开启蜂窝数据；不要给 10010 以外的号码打电话或发短信。
- 页面提示“结果不确定”时，不要重复点发送，先记下提示原文。
- 记录里不要贴机器人地址、token、完整手机号和验证码正文，写“已填写”即可。

## 1. 短信转发

### 前提

- 设备已装含新通道的版本（页面“短信转发”的发送器下拉里能看到钉钉、企业微信、飞书、Server酱、PushPlus、Gotify）。
- 准备至少一个真实通道。建议先用 Bark 或飞书群机器人，各家要准备的东西：

| 通道 | 要准备什么 |
|---|---|
| Bark | 服务地址（如 `https://api.day.app/`）和设备 key |
| Telegram | bot token 和 chat ID（设备所在网络要能访问 Telegram） |
| 钉钉群机器人 | Webhook 地址；安全设置选“加签”时再准备 SEC 开头的密钥，选“关键词”时把 `RustSimHub` 设为关键词 |
| 企业微信群机器人 | Webhook 地址 |
| 飞书群机器人 | Webhook 地址；开了“签名校验”时再准备密钥，用“关键词”时加 `RustSimHub` |
| Server酱 | SendKey（只支持 sctapi.ftqq.com 的经典版） |
| PushPlus | token |
| Gotify | 自己的 HTTPS 服务地址和应用 token |
| Webhook | 任意 HTTPS 地址，可选 Bearer |

### 步骤 A：合成测试（不涉及真实短信）

1. 打开 设置 → 设备调试 → “短信转发 · 开关与规则”，点“管理登录并读取”。
2. 点“新增目标”，选发送器，填凭据。钉钉、企业微信、飞书、Server酱可以直接粘贴完整地址。
3. 点“新增规则”，目标选刚才那个，其余条件留空，保持“仅通知”。
4. 点“保存目标和规则”。
5. 点页面上的“合成测试”，对这个目标发一次。

**通过：** 手机或群里收到一条带“合成测试”字样的消息，页面显示“已确认”。

**失败时带回：** 选的通道、页面提示原文、对方有没有收到。

### 步骤 B：故意填错（失败路径）

1. 把同一目标的凭据改错一位（勾选“替换此目标的地址和凭据”后重填），保存，再发一次合成测试。
2. 改回正确凭据。

**通过：** 页面显示“失败”或“结果不确定，不会自动重发”，**不能显示“已确认”**；对方没有收到；设备没有自己反复重发。

### 步骤 C：真实短信

1. 点“开启转发”。
2. 用自己的手机给棒子里的号码发一条不含隐私的短信，例如“转发测试 1”。
3. 把规则改成“完整正文”，保存，再发一条“转发测试 2”。
4. 测完点关闭转发（如果不打算长期开着）。

**通过：**

- 第一条只收到“收到一条新短信”的提示，不含号码和正文。
- 第二条收到发送方、时间和完整正文。
- 每条短信每个目标只收到一次。
- 设备页面的收件箱里两条短信都在。

**失败时带回：** 哪一步、对方收到了什么（打码）、页面“核对上次请求”显示的状态。

### 步骤 D：重启后还在不在

1. 转发保持开启，把棒子断电再上电，等 2 分钟。
2. 再发一条“转发测试 3”。

**通过：** 不用重新登录页面，仍然收到转发。

## 2. AirSIM iPhone 直连（配对与短信）

这一章测配对、状态和短信。通话控制单独在第 3 章；通话声音还没有接入。

### 前提

- 设备已装含 AirSIM 的版本：安全策略页能看到“AirSIM 手机直连”卡片。
- iPhone 装好 AirSIM App，和棒子在同一个 Wi-Fi 下。记下 App 的版本号（设置里能看到）。
- 设备页面刚登录过（所有者权限只在登录后 5 分钟内有效，超时就重新登录）。

### 步骤 A：启用和配对

1. 打开 安全策略 → “AirSIM 手机直连”，点“读取状态”，再点“启用”。
2. 点“开始配对”，页面显示六位验证码和端口（7594），120 秒内有效。
3. iPhone 上 AirSIM：设置 → 安卓连接 → 配对安卓手机 → 选“私网 IP”，打开“本地模式配对”。
4. 地址填棒子的 IP（192.168.120.167），端口填 7594，输入验证码，点“连接并加密配对”。

**通过：** App 提示配对成功并显示设备名 RustSimHub；设备页面点“读取状态”后，列表里多出一台 iPhone。

**失败时带回：** App 的提示原文（截图最好）、App 版本号、页面“读取状态”后显示的内容。

### 步骤 B：故意输错（失败路径）

1. 再点一次“开始配对”，在 iPhone 上故意输错一位验证码。
2. 然后用同一个窗口输入正确的验证码。

**通过：** 输错时 App 提示失败，设备列表不增加；随后输对可以配对成功（输错不会让这个窗口作废）。

### 步骤 C：短信

1. 用自己的手机给棒子里的号码发一条“AirSIM 测试 1”。
2. 看 iPhone 的 AirSIM 里是否出现这条短信（App 需要开着或在后台保活）。
3. 在 AirSIM 里给 10010 发一条“CXLL”。

**通过：**

- 配对之前收到的旧短信不出现在 App 里，只出现配对之后新收到的。
- 新短信出现在 App 里，内容完整。
- 发给 10010 的短信在设备页面的短信记录里能看到，并收到运营商回复。

**失败时带回：** 哪一步、App 里显示了什么、设备页面收件箱里有没有这条。

### 步骤 D：解除和停用

1. 设备页面点这台 iPhone 的“解除配对”，确认。
2. 在 App 里刷新或再发一条短信。
3. 重新配对后，点“停用”，再在 App 里操作一次；然后重新“启用”。

**通过：** 解除后 App 立即连不上；停用后 App 连不上，重新启用后不用重新配对就能继续用。

### 步骤 E：重启

1. 配对保持，把棒子断电再上电，等 2 分钟。

**通过：** App 不用重新配对就能恢复连接。

### 这一章不测的

- 通话声音（未接入）。通话控制见第 3 章。
- 锁屏来电唤醒（需要 AirSIM 的云端推送，不在本地直连范围内）。
- 8 kHz / 16 kHz 切换（设置能保存，但音频通道还没接，切换目前没有效果）。

## 3. AirSIM 通话控制（没有声音）

这一章只验证“电话能不能拨出、接起、挂断”，**听不到声音是预期**。需要含通话控制的版本（设备页面 AirSIM 卡片的说明里写着“通话控制”）。只打 10010。

### 步骤 A：拨出和挂断

1. 在 iPhone 的 AirSIM 里拨 10010。
2. 看 App 是否依次显示拨号中、接通。接通后按几个数字键。
3. 在 App 里挂断。

**通过：** App 的状态跟着变化；设备页面的通话记录里出现这通电话；挂断后 App 和设备页面都显示已结束。听不到 10010 的语音属于预期。

### 步骤 B：来电

1. 用另一部手机拨打棒子里的号码（AirSIM 需要开着或后台保活）。
2. App 出现来电后点接听，几秒后挂断。
3. 再打一次，这次在 App 里点拒接。
4. 再打一次，不接，让它自己挂断。

**通过：** 三次分别表现为接通、对方被挂断、App 里记为未接来电。

### 步骤 C：断开保护

1. 在 App 里拨 10010，接通后直接把 iPhone 的 Wi-Fi 关掉。
2. 等 1 分钟，看设备页面的通话状态。

**通过：** 这通电话在大约半分钟到一分钟内被棒子自动挂断，不会一直占线。

### 步骤 D：两边抢线

1. 在设备网页上拨 10010（不要在 App 里拨）。
2. 在 App 里尝试挂断或再拨一通。

**通过：** App 提示线路由其他设备控制，网页那通电话不受影响。

**失败时带回：** 哪一步、App 的提示原文、设备页面通话记录里这通电话的状态。
