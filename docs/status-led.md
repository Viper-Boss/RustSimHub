# UFI003 指示灯约定

用户于2026-10-21确认以下规则。实现/实机验收以HANDOFF顶部为准；本表不是已全部验收的声明。

| 情况 | 指示 |
|---|---|
| 系统关键服务故障 | 红色常亮 |
| 新鲜Core提示正在响铃 | 白色快速闪烁，约400毫秒一轮 |
| 蜂窝数据已连接，且有可用互联网；可同时有Wi-Fi | 绿色常亮 |
| 只有Wi-Fi，且可访问互联网 | 蓝色常亮 |
| 无Wi-Fi/蜂窝连接，或连接后不能访问互联网 | 黄色常亮 |
| eMMC发生读写 | 青色120毫秒，最多每5秒一次，随后恢复原色 |
| USB配置、首次配置或已授权网页配置会话 | 白色慢节奏，约6秒一轮 |
| 已验证的新固件可更新 | 紫色200毫秒，每10秒一次，随后恢复联网原色 |
| 固件升级中 | 紫色慢节奏，约6秒一轮 |
| 未读短信 | 黄→紫→黄→紫，每色280毫秒、间隔20毫秒，共1.2秒 |
| 未接来电未确认 | 红→紫→红→紫，同上，共1.2秒 |
| 两类未读同时存在 | 红→黄→紫→红→黄→紫，共1.8秒 |

2026-10-28 用户改定未读配色：原短信“蓝→青→绿”的蓝、绿与 Wi-Fi/流量底色相同，看不出来；新配色不使用蓝、绿、青。注意黄色也是“断网”底色、紫色也用于升级提示，但未读组是 0.3 秒一换的连续变化，和常亮或 6 秒慢节奏可以区分。

未读动画最多每30秒一组，查看/确认后停止对应提醒；高优先级状态期间不播。优先级：关闭指示灯→来电快速白闪→故障→升级→配置→未读提醒→新固件提醒→读写→联网原色。关闭指示灯指用户显式关闭灯，不是退出网页配置。退出网页配置必须恢复下层状态。

USB只是接入方式；连接NAS本身不代表仍在配置。首次尚未完成配置时显示白色；USB初始化进行中也显示白色。网页配置用经过权限检查的短租约，关闭/保存退出释放，异常断开最长30秒恢复；浏览未授权页面不能改变灯。

本板三个通道为gpio-leds，max_brightness均为1。红绿合黄、绿蓝合青、红蓝合紫、三色合白；须实物确认混色。该接口只支持开关，当前实现的“呼吸”是慢明暗脉冲，不能宣称连续亮度渐变；不在弱CPU上高频写sysfs模拟PWM。

灯控程序只写三个固定LED sysfs路径，空capability，不能控制任意GPIO、网络配置或短信/通话。Core输入仅包含30秒内租约及两个未读布尔值，不传消息内容、号码或身份。升级输入只能由Root更新执行器发布，不能以GitHub存在新提交冒充已验证升级。

联网判断使用NetworkManager的每设备缓存连通性。主动探测只允许wlan0，使用Debian的连接检查端点，每120秒、4秒超时；其余接口明确关闭探测，尤其不能对WWAN启用普通APN或探测流量。全局状态不等于本设备的Wi-Fi状态。参考[NetworkManager配置文档](https://www.networkmanager.dev/docs/api/latest/NetworkManager.conf.html)的device.check-connectivity和connectivity节。探测端点不可用/门户也会显示黄色，不能把此灯当成完整互联网可达性保证。

## 直接读取系统缓存状态

主线17d4707起，灯控采样直接读取固定系统总线的PID1/NM缓存属性，生产路径不再启动systemctl/nmcli。仅访问固定十个单元及最多16个唯一NM设备；不Load/Start/Reset单元、不扫描/激活网络、不取设置秘密、不调用连接检查。每轮固定唯一owner并前后复核；缺失、异常或超时继续按原错误输入处理。

采样完成后休眠15秒，整轮读取截止3秒，故障观察延迟上限约18秒加调度开销；LED-02继续保持至少25秒再观察。动画20ms、业务/升级提示200ms读取和颜色优先级保持。已有文件但未加载的单元只读取文件状态，按inactive处理；未知文件/状态拒绝。IPv4/IPv6互联网判断只用已激活设备的已有full缓存，包含wlan0和蜂窝；unknown/none仍保守处理，绝不为蜂窝主动探测。

服务/网络快照由渲染线程独立检查30秒有效期，计时从查询开始，包含查询本身的耗时。正常约18秒采样间隔保持可用；采样线程意外退出、阻塞或没有发布新结果时，过期快照的联网/配置/升级声明全部丢弃，改为故障输入，不能无限保留旧蓝灯/绿灯或白色初始化提示。新查询结果到达后自动恢复当前状态，不重启服务、不增加查询或GPIO写入频率。显式关闭及单独新鲜Core来电提示继续按原优先级生效；正常查询错误仍立即进入原故障路径，不等待30秒。`--build-info`公开`status_snapshot_max_age_ms`供制品核验，实际安装版本以HANDOFF及部署记录为准。

本机`--probe-readonly`仅输出服务/网络采样布尔值，不写GPIO；不包含Core业务提示或完整动画状态。性能、真实受限服务和物理灯效以本轮验证记录为准，不能以此命令替代真人验收。已复用仓库锁定的tokio/zbus版本，无新增版本或Root能力。

## 接线与验收边界

当前灯控源码包含完整策略和固定设备输出、Core配置租约、网页保存/退出/关闭提示，以及未读/升级事件接线。网页提示需要network.manage权限；仅status.read的客户端不能改变配置指示。每个页面独立view_id，客户端串行发送结束动作，服务端25秒到期；Root读到的Core输入还必须在10秒内保持新鲜，且来自UID986/GID0、2750目录中的单链接0640普通文件；空capability的Root经root组读取。

未读是设备级提示，不继承NAS旧用户的历史标记。Core仅从当前line_epoch的业务库做只读投影，换SIM后未重新观察的通话不能触发提醒；接通过的呼叫不会误作未接。读取详情不自动确认，网页成功展示后另发notification_read；需要对应sms.read/calls.read并验证记录存在，标记持久保存成功才返回成功。UI标记单独保存为Core私有state/indicator-read.json，该提示元数据未引入数据库迁移；当前schema见HANDOFF/实际build-info。单独SQLite备份不包含这个可重建的提示元数据。首次接入时将已有记录作为基线，避免历史记录集中闪灯。

未读输入不包含号码、正文、消息ID或SIM标识。只在业务事件版本改变时重新拉取有界记录投影；持久读标记仅在变化时写入，输入提示落在/run，不制造eMMC读写提示循环。网络/服务采样在独立线程，不能拖慢0.9/1.8秒动画。配置、升级等高优先级状态阻止未读动画；退出后仍有未读会继续每30秒提醒。

新版本提示读取固定Root更新存储中已经过签名/载荷验证的candidate记录，要求比confirmed版本新且不超过floor；未尝试为紫色短闪，正在试运行且尚未确认则为紫色慢脉冲。Root更新程序stage/choose期间另发布有界活跃提示，退出/失败清除，异常死亡最多10秒过期。没有自动更新源检测，不把GitHub新提交当作可安装固件。

实机已安装独立灯控，服务启用、空capability、三个固定sysfs写入范围、白色配置脉冲读回均通过，用户确认“白色慢速亮灭正常”。这是早期白灯记录；当前已初始化业务和实际运行版本见HANDOFF。网页/真实未读/升级/蜂窝的完整灯效仍待集中真人验收，不能用策略、IPC或只读探针替代。最终运行版本及制品入口见HANDOFF。
