## 问题与实现

旧版pending.load在localStorage消失时返回空记录，pending.save也可能直接成功返回。已打开的页面因此可能在没有保存操作编号时仍发送setup_ap_start。新增失败路径测试在旧生产页面上实际复现了该请求，保留失败日志。

现在读取必须获得可用存储；每次设置或删除后核对读回值，再向控制器确认成功。页面登录后失去存储、写入前失去存储、写入没有生效、试连/保存/扫描编号写入失败时，原有进度保持，不发送对应网络变更；密码和派生密钥仍仅在页面内存中。

原archive回调为空，但控制器完成提示称回执已保存。现为每设备最多保留最近8份saved/closed回执，只包含严格校验的操作元数据。归档写入失败不清除当前操作；归档成功但清除失败时，重查后可以复用同一回执，不重复归档或重新提交Wi-Fi保存。损坏、重复ID或冲突回执拒绝，不通过清空记录继续。JSON读取错误改为固定中文信息，不把损坏存储片段显示到页面。

这仍是localStorage接线：回读不是文件系统fsync，也没有新增跨标签事务或声称localStorage的比较与写入具有跨文档原子性。Core/Root的唯一操作、幂等和权限门禁保持原实现；本修复不以浏览器记录替代设备权威回执。
