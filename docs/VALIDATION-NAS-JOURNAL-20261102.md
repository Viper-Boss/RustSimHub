# NAS本机操作回执导出与清理

## 问题和实现

NAS管理此前最多保存64条本机回执，满额后只提示维护留存，没有实际导出和释放空间的路径。主线在 `crates/edge/src/web/nas-bridge.js` 完成有限导出/清理，装配于默认折叠NAS面板的“本机回执留存”，不增加首页测试按钮，不改变Core、Root、设备schema或成员任务。

用户先准备导出，再下载JSON并自行确认文件已保存，最后明确清理。浏览器不能证明文件实际保存；点击下载不自动删除。文件只包含当前已验证设备pin的NAS意图/回执公开元数据，保留 `source:reply` 与 `source:current_state` 的区别。它不是原操作成功的补充证明，不含种子、私钥、会话令牌、短信正文，也没有导入执行能力。设备/NAS公开标识仍需妥善保管。

读取待确认意图和回执采用单一IndexedDB事务快照。清理同样在一个读写事务中读取两键，只写回回执键；逐条核对本次导出记录未变化，整笔拒绝更改/缺失冲突。其他设备、新增回执、待确认意图及其关联回执均保留。失败不进行部分清理，不发Core请求、不重放保存/撤销、不改变棒子数据。

导出链接为本机Blob URL。退出、隐藏页面或会话切换时撤销链接和清理上下文；迟到读取不能生成下载，清理在写入前重新核对页面代次与已验证pin。读库错误、超额、重复编号、跨pin、额外敏感字段和配额失败均拒绝。
