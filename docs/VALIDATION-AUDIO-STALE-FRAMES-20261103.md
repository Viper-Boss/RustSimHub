# LAN音频过期帧丢弃与会话持续

## 问题与范围

既有PCM队列按60ms帧龄丢弃过期数据，但 `Session::send` 对编码前/编码中已经过期的帧返回Codec/Bounds。生产worker把这些错误作为媒体失败退出，因此一次调度或编码延迟就可能结束仍有有效权限的LAN会话。

本批只改已有LAN音频发送处置及其合成自检，不接管成员D的TURN/远程通道、Core恢复、Auth或Storage实现。未改60ms上限、四帧队列、SDP/DTLS身份、票据/Permit、媒体超时或PCM错误策略，没有新依赖、权限、Root角色或协议版本。

## 新行为

- 编码前使用当前时钟复核权限/连接/编码器；已过期帧计入丢帧并返回，后续新帧仍可发送。
- 编码后再次检查实际时钟和权限；期间过期的编码包不写入RTP，不增加真实发送数，会话继续。
- 未来时间戳仍是错误；缺失/撤销授权先于丢帧判断拒绝，不能用过期帧掩盖授权失败。
- 没有给旧音频改时间戳，没有放宽帧龄，也没有让任意远端输入控制时钟。私有时钟参数只供模块内部和测试，公开send仍使用实际BOOTTIME。
- 自检保留sent_each字段但改为实际两侧发送数的最小值，另列尝试/发送/丢弃数，不再无条件自报50。

## 未解决和交付边界
