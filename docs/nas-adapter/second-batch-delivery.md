## 主线集成步骤

1. 以本 PR 正文的完整 HEAD 核对文件边界与 CI；新增提交后重新确认，不沿用旧审核。
2. 在 Linux 准备仓库锁定 Rust、Go 和 python3，运行 compat 测试、严格 Clippy、fmt、Go test/vet。C-06 的专用 ignored worker 必须由父测试实际运行，Go 的真实 Linux CLI 夹具不能跳过。
3. 仅由主线在获得真实数据授权后准备关闭且完整的 SQLite backup 私有副本；固定来源 namespace。先运行 `preflight SNAPSHOT SOURCE [ARCHIVE]` 并核查有限报告，不把报告作为写入授权。
4. 导入是离线操作。查询器持有共享 archive 锁时应停止本轮并按维护流程安排停读；不能删除锁文件、解除保护或自动重试来抢写。
5. 原 `import SNAPSHOT SOURCE ARCHIVE` 仍重新检查完整输入并在同一事务提交记录和批次。冲突保持原库，交主线核查；不改 namespace 来隐藏同源冲突，不复活 tombstone。
6. 实际归档内容变化后，旧 access 绑定可能失效。保留原 access，由 Owner 核验来源并显式选择新的私有 ACCESS_DIR、重新授权；不自动清空授权库。旧游标不是授权，历史 ID 不能用于当前发送/呼叫。
7. 回退本批只需回退测试/文档提交，无产品格式迁移、业务数据或设备状态需要恢复。
