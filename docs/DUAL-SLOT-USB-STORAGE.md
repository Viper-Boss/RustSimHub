# UFI003 A/B 固件、独立数据分区与 USB 接管

## 已提交的实现

- RustFlashKit 的「识别型号和容量」读取主备 GPT，按出厂固件标签报告型号，给满足条件的 UFI003 生成 A/B 分区预览。型号不明时只展示已确认的容量和原分区。已启动的候选固件另外可通过 USB 串口读取设备树型号与内核报告的 eMMC 容量。
- RustSimHub 的槽状态规则支持写入前撤销非活动槽的可启动状态、通过完整校验后登记候选、两次试启动、健康确认，以及手动选择可用备用槽。离线候选已经接入 initramfs、持久账本和运行层健康确认，仍需真机验收。
- USB 维护接口与原有 NCM 网卡并列。候选系统在内核提供 CDC ACM 功能时建立 `/dev/ttyGS0`，由独立设备单元直接读取请求。现有指令可读取设备信息及 SSH 状态、持久启停 SSH。RustFlashKit 图形界面与 CLI 已接入。Linux SSH 登录依旧使用原先安装的维护公钥，即使开关通过 USB 打开。

## 分区规则

| 分区 | 4 GB 档 | 8 GB 档 | 内容 |
| --- | ---: | ---: | --- |
| RSH_A | 1328 MiB | 1792 MiB | 系统槽 A |
| RSH_B | 1328 MiB | 1792 MiB | 系统槽 B |
| RSH_RECORDS | 64 MiB | 256 MiB | 本地短信、通话记录 |
| RSH_CONFIG | 64 MiB | 128 MiB | 配置、初始化标记与常驻业务设置 |
| RSH_ABUSE | 32 MiB | 128 MiB | 预留反滥用数据库 |
| RSH_KEYS | 32 MiB | 64 MiB | 设备证书、信任根、公钥、NKN 与 SSH 私钥 |
| RSH_BOOTCTL | 8 MiB | 8 MiB | 选槽、尝试次数及健康确认账本 |
| RSH_AUDIO | 余下最大连续区，至少 64 MiB | 同左 | 本地录音与 NAS 重传队列 |

现役 4 GB 布局的脱敏几何可为录音分出 549 MiB。8 GB 使用合成 GPT 验证计算逻辑，待读取真实 8 GB 分区表。以实际可回收的连续扇区为准，保留基带、NV、校准、引导链、未知区和未分配间隙。容量档位依据 GPT 备份头已读回的末扇区，运行中的 USB 通道另报内核读取的 eMMC 容量。仅复用已识别的旧系统区。空间不足、目标镜像过大或原布局不匹配时停止生成计划。旧 GPT 表项容量不足时计划扩至 128 项，现有保护项的索引、起点和终点全部保留。

系统槽交替更新。早期启动组件读取两个带代次和校验的选槽记录，试启动前先持久化扣减次数。独立看门狗负责失败重启。启动与业务检查成功后，确认当前实际运行的槽位及其镜像身份。升级页保留「下次启动使用备用固件」，由受信任入口安排一次候选切换。A/B 页面移除手动删除备用固件的按钮。两份系统各使用独立分区标识，固定的早期启动层通过选槽记录选择根分区。新包写入非活动槽，并在完整回读后登记候选。已确认槽与共用数据分区在安装时保持可恢复。

当前设备仍从固定 `rootfs` 启动。完整安装还需要实际选槽引导、看门狗、固件签名和写后核验、共同数据分区挂载与停机迁移。已知旧紧凑镜像为 1,456,963,584 字节，超过 4 GB 档的单槽预算，需重新生成更小的镜像并验证。初装刷写前要读回备份、确认恢复入口并验证目标镜像与硬件。现有一键刷机继续沿用旧流程，本次预览没有连接到 GPT 写入。

## USB 物理信任

| 连接 | 权限入口 |
| --- | --- |
| 刷机工具，9008 物理 USB | 底层维护使用直连设备。写入计划、载荷完整性与保护区核对用于防止误刷 |
| 刷机工具，运行中的 USB 串口 | 设备本地管理员，无需账户、配对或维护密钥 |
| NasSimHub，运行中的 USB 串口 | 目标权限为业务和设备管理的本地管理员，接线后直接取得，拔线后释放 |
| Wi-Fi、蓝牙、NKN、其他网络入口 | 继续验证各自的账户、会话或配对权限 |

USB 权限绑定内核提供的 tty 文件描述符。原来通过 USB 网卡打开的 HTTPS 页面继续使用网页登录规则，IP、请求头与网页会话均无法获得串口权限。NasSimHub 的后续接管应通过独立 USB 通道拿到仅本次接线有效的业务控制权，复用已有命令、日志、媒体与写入校验。NAS 用户的外部权限仍由 NasSimHub 检查。设备端应保持唯一的通话业务控制者。通过 USB 向 NasSimHub 转发的范围为业务数据和实时语音，蜂窝上网流量不走此通道。

现有串口协议每次一条 ASCII 指令，格式为 `RSHUSB1 <命令>\n`，每条回复一行 JSON。首次发 `IDENTIFY`，回应含 `protocol: 1`。已实现 `DEVICE_INFO`、`SSH_STATUS`、`SSH_ON`、`SSH_OFF`。断线或结果不明时应重新读取状态后再操作。SSH 持久开关目前沿用旧状态目录。NasSimHub 接管、媒体与业务服务还未接线。

## 首启、记录与录音

- 首启向导初始化独立数据盘、生成每台设备的 NKN 地址、选择 NAS 存储和 NasSimHub 业务连接、SSH 开关和胖瘦模式。配置中的连接参数进入配置分区，证书与私钥进入密钥分区并限制读取权限。
- 胖模式默认保存本地短信、通话记录与通话录音。瘦模式默认关闭这三种本地存储，由 NasSimHub 保存，用户可逐项开启。已有记录与旧模式的数据迁移到相应分区。
- NAS 在线时用有界内存直接上传录音。接收方持久保存并确认同一录音 ID、长度及摘要后，再释放本地缓冲。离线或缓冲耗尽时，将录音存入录音分区，然后按原 ID 补传，重试去重。提前收到分段回执时只回收已确认保存的内存段。
- 录音分区在新写入预计达到 80％ 或实际达到 80％ 时按时间回收已完成的旧录音，优先删已在 NAS 确认的文件，低于 80％ 时保留剩余文件。正在录制与上传的文件持有占用标记，回收跳过。瘦模式的本地记录开关关闭时，存储由 NasSimHub 负责。
- 反滥用分区先留容量和文件系统边界。规则库及拦截功能留给后续版本。

已接入 A/B 候选的分盘挂载和首次安装材料构建。首启向导、数据迁移、录音流程及 NasSimHub 接管仍需接入。详见[运行层预检](VALIDATION-AB-RELEASE-PREFLIGHT-20261124.md#固件运行层)。
