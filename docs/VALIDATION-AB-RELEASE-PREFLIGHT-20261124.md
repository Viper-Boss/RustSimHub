# 2026-11-24 双槽刷机发布预检

## 已验证

从已存在的 UFI003 单槽刷机包读取签名清单，使用 UsbTool 预置的公钥验签，并逐块核对临时 rootfs 副本和清单的 SHA-256。旧镜像为 1,456,963,584 字节。该副本用 `resize2fs` 缩至 1,392,508,928 字节（1328 MiB）。缩小前后的 `e2fsck -fn` 均退出 0，12,407 个文件和 110,821 个已用块一致。该检查确认旧 ext4 内容可以装入 4 GB 双槽布局的任一槽。临时副本保留旧文件系统标识，仅作为容量证据。

读取同一个签名包的 boot 头，启动参数为 `root=LABEL=rootfs`。刷机包清单只列出 `aboot`、`boot`、`NSHSTATE`、`rootfs`。它使用原单槽布局，不能用来安装双槽系统。检查期间未访问或改写任何棒子。

## 发布边界

RustFlashKit 使用 GitHub Actions 构建 Windows x64 工具预览。流程固定工具源码和上游 EDL 归档摘要，执行测试与打包后自检，发布图形版、CLI、校验文件和对应的 EDL 源码。高通 Firehose 加载器由使用者另外选择。预览提供型号、容量与只读 A/B 布局，目标设备的实时 USB 维护需要相应的候选固件。

A/B 整机包暂未形成。真实的早期选槽、试启动失败回退、共同数据分区挂载、首次初始化和刷机工具的 A/B 写入还未接通。待验证的设备路径是单台 UFI003 的首次启动、完整读回、断电重启和失败回退，8 GB 另外需要真实分区表核对。

## Windows 工具发布结果

GitHub Windows x64 构建通过 257 项测试。两个 EXE 已打包，命令行包的只读护栏及 Windows libusb 自检通过。公开发布页回读确认两个 EXE、SHA-256 校验文件和上游 EDL 源码，清单与 GitHub 资产摘要一致。[Windows 工具预览发布](https://github.com/Viper-Boss/RustFlashKit/releases/tag/v0.1.0-ab-preview.1) · [构建日志](https://github.com/Viper-Boss/RustFlashKit/actions/runs/45331131839)。

## A/B 启动镜像离线候选

基于锁定摘要的 64 MiB UFI003 boot，保留原 ARM64 内核和附加设备树，重新构建带静态选槽程序的 initramfs。启动脚本在挂载根盘前，从内核枚举的同一 eMMC 上寻找 RSH_A、RSH_B、RSH_BOOTCTL。8 MiB 启动控制区的记录相距 4 MiB，使用代次和 CRC 校验。候选试启动前先写另一份记录、同步并回读。两次未确认后回到已确认槽。无有效记录、同代记录冲突等情况停止选槽。

用 Zig 0.14.1 生成 ARM64 静态程序，QEMU 用户态运行验证了两次试启动后回选、损坏记录继续使用旧记录、冲突或空记录被拒绝。镜像写入普通文件后重新拆包，核对内核、启动参数、initramfs 和注入内容。SHA-256 为 `49284610866e4cfba5538dd4998c65a12867e72c9312723a41258047acc98021`。系统专项套件执行 219 项，其中通过 106 项、跳过 113 项。没有进行物理设备写入或系统级启动。

启动候选仅保存在主机私有共享目录。旧系统仍依赖 NSHSTATE 的固定挂载和守卫。新数据分区迁移、候选健康确认、看门狗、A/B 刷写、签名整机包以及真机启动与掉电回退仍需接线和验收。

## 固件运行层

启动选择器在切根前保存本次槽位、启动代次和试运行状态。运行层按实际根分区号核对该记录。共享存储、应用服务组、Core、Edge 和 Core 本地身份探测连续两次通过后，按同一代次确认新槽。健康未达标且启动账本仍指向本次试运行时请求系统正常重启。两次试运行耗尽回到原槽。当前已确认槽可以用 Root 本地 `rustsimhub-firmware-slot rollback` 预约下次启动使用已验证的备用槽，命令本身不重启。网页按钮待接入。早于用户态的硬挂起仍需硬件看门狗验证。

组合器按启动镜像回读报告导入同一 SHA-256 的 ARM64 选槽程序。仅显式选择 A/B 组合时启用新分区挂载和健康定时器。旧单槽仍使用 NSHSTATE。A/B 共享系统配置、应用版本、设备识别名和 Wi-Fi 配置。Core 的业务库由 RSH_RECORDS 提供，Core 身份、Edge 证书与配置、SSH 密钥和 NKN 目录走 RSH_KEYS。RSH_AUDIO 与 RSH_ABUSE 分别挂载，录音运行时和反滥用规则仍待实现。

内部镜像构建支持按 4 GB、8 GB 选用不同大小的根文件系统，并给 A、B 分配不同的标签与文件系统 UUID。离线数据镜像构建为两档已识别布局各生成六个共享分区镜像。逐一核对长度、标签、权限、根目录所有者和 ext4 完整性。首启仅写入请求标记与经摘要核对的维护公钥。启动账本初始只认可 A，待刷写器完整读回另一槽后才能标记 B 可用。

新版 boot 候选 SHA-256 为 `f04f14a0e9cc5fb0274fe9338051c19309fcee5d974a2676555878664d16a526`。ARM64 QEMU 验证同代确认、拒绝过期结果、手动预约和失败回退。225 项系统测试中 112 项通过，113 项因环境或现有条件跳过。共享目录保存新的 boot、对应选择器及回读报告。核验没有启动或刷写实体棒子。完整签名整机组合、刷机工具实际的 A/B 写入与读回、旧数据迁移及备用棒子真机验收仍待完成。
