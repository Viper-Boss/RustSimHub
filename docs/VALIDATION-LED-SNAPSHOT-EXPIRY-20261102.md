# 灯控采样失效的主线修复

## 问题与最终行为

原渲染循环直接复制共享`Inputs`，采样线程没有更新时间字段。正常查询错误会产生故障输入，但线程异常退出或长期不再发布时，旧联网、配置或升级状态可以一直保留。这个缺口来自源码路径核对，本轮没有在棒子上制造采样线程异常。

主线增加私有`Snapshot`，同时保存输入与查询开始的单调时间；渲染端每帧独立检查30秒有效期。过期或未来时间记录返回干净的故障输入，旧联网/配置/升级声明不再生效；有效的新结果到达后自动恢复。正常3秒查询预算与15秒休眠仍保持，约18秒间隔不会误判过期，查询耗时包含在30秒内。

显式关闭和新鲜Core来电提示仍在现有位置应用，原颜色/提醒优先级、200ms提示读取、20ms动画循环与固定GPIO路径不变。没有新依赖、协议、数据库迁移、权限或网络操作。`--build-info`只额外公开`status_snapshot_max_age_ms:30000`，不是健康或物理灯效证明。
