# 需求备忘：外呼与发短信的激活限制（用户 2026-10-28 提出，暂不实现）

本文只记录需求，以及动手前必须先弄清的技术风险。**还没有任何实现，也没有对设备做任何调查或写入。**

## 目的

棒子基于高通 MSM8916（410），用来转发短信和来电。为符合法律法规、防止被用于电信诈骗和骚扰电话，**默认只开放“转发短信”和“转发电话”**；主动打电话和发短信必须单独激活，并且严格限制。

## 用户规定的规则

| 规则 | 内容 |
|---|---|
| 默认能力 | 只能转发短信、转发电话；不能主动呼出，不能发短信 |
| 激活入口 | 设备开机时间累计满 **168 小时**后，才出现“绑定激活”按钮 |
| 绑定内容 | 设备识别码 + SIM 卡 ICCID；把哈希值放进 TEE，关键数据不让外部拿到 |
| 换卡 | 首次绑定满 **180 天**后才能换卡 |
| 绑卡上限 | 一台设备终身最多绑定 **10 张卡**（理论上约 5 年用完） |
| 不可逆计数 | 每绑定一张卡，熔断 410 芯片上的一个 eFuse 位，防止刷机后绕过 |
| 不满足条件时 | 时间没到、超过 10 张或卡不符时，只能转发，不能打电话、发短信 |
| 防篡改 | 系统内文件被破坏时，模组直接停止工作并锁死（用户底线：正常使用者不会破解，破解者多为电诈、传销） |

## 动手前必须先弄清的风险（实施前逐条确认）

1. **TEE 能否使用。** MSM8916 的 TEE（高通 QSEE）一般只加载带厂商签名的安全应用。这根棒子的 OEM 签名密钥大概率拿不到，自定义的校验程序可能根本装不进去。需要先**只读**调查安全启动和 QSEE 的状态，再判断可行性；不行的话要找替代方案，例如 Linux 侧签名配合只读分区。
2. **eFuse 熔断不可逆，风险很高。** 熔错一位可能导致芯片无法启动，或者把安全启动锁死，设备直接变砖。现有项目规则已经禁止写基带、NV、校准分区，eFuse 的风险比这些更高。必须先确认有哪些厂商留给用户使用、熔断后不影响启动的位，而且只能在**备用板**上先做实验，不能拿正在用的这根试。
3. **“破坏就锁死”要防误伤。** 断电导致的文件系统损坏、正常的签名升级、恢复流程（REC-02/03），都不应该触发锁死。需要和签名应用组、回滚、恢复演练一起设计；锁死之后的合法解锁路径也要事先定好。
4. **计时可信度。** “累计开机 168 小时”“绑定满 180 天”需要防止被篡改的时间来源：设备没有可信的电池时钟，网络时间也可能被伪造。需要设计单调计数和持久化方式。
5. **法规边界。** 激活流程应当记录必要信息，但要遵守项目的隐私规则：ICCID、设备识别码等原始值只放在私有目录或 TEE 中，不进入日志或提交。
