## 用户操作

1. 在“配置 Wi-Fi”填写名称和密码，点击“开始试连”。加密方式明确为 WPA2 个人网络/AES；输入支持隐藏 SSID。
2. 页面显示试连进度；设备返回配置热点并提供成功证明后，出现“确认保存并连接”。
3. 用户明确确认后才请求保存。保存完成以设备的完整回执为准。结果未确认时保留编号，提供“查询进度”和“结束本次配置”。

每个阶段只显示适用的按钮；结束证明核对后才显示“完成并保留回执”。操作编号默认折叠。配置热点来源下隐藏日常电话、短信、网络和复杂调试区域，保留身份与配网入口。常规管理地址继续保留原有折叠入口。

保存切换网络后需要在目标网络继续管理。稳定来源、证书、地址发现及浏览器 Owner 身份交接仍属于 AP-08，当前网页未解决这一整条路径。因此页面断开不会被当作保存成功，刷新也不会自动重新创建事务。

## 一个事务与刷新恢复

浏览器以 IndexedDB 的原子 compare-and-swap 保留一个配网记录，校验 ID 和 revision。开始热点、试连、保存、取消均先持久记录本次 ID，再请求设备。另一页更新记录后，旧页面停止提交并要求查询。归档只保存元数据及已核对的终态；最多保留 32 份回执。

记录严格限定为 format、浏览器事务 ID、revision、来源、随机开始键及其摘要、父操作 ID、有限试连/保存 ID 列表和取消标记。SSID、密码、token、凭据摘要都不会写进配网草稿或回执。试连/保存历史最多各 16 个，失败后的新操作仍保留旧编号。

丢失开始回复时，浏览器使用随机开始键摘要找到原父操作。丢失试连或保存回复时，只查原 ID；`not_found` 明确不证明未执行。关闭、退出和 pagehide 会清除输入与内存中的凭据并中止后续页面动作；设备负责自己的有限租约清理。重新打开后确认保存需重新输入相同凭据，由设备核对与原试连一致。

网页观察最多 60 次/65 秒，单次 API 仍使用既有 18 秒截止。三次连续查询异常结束本轮观察并保留记录。最后一轮恰好收到成功结果时不会被观察截止覆盖。归档失败会恢复到可查询状态，保留原记录，不重新提交保存。

配网记录未核清时，现有电话、短信、Bark 一键测试及手动动作会提示先完成配置；Core 的业务互斥和当前 Owner 权限继续作为实际执行边界。

## 新增 Core 只读接口

`setup_ap_operation_status { token, request_key_sha256 }`：只接受 64 位小写十六进制随机开始键摘要。要求当前 Owner 和 network.manage，委托客户端与错误 token 拒绝；路径、额外字段和大写摘要在 Wire 拒绝。

接口读取当前 Owner/realm/设备身份匹配的私有 intent。当前会话返回原操作 ID 和可用能力；Core 重启后可校验持久 Closed 或独立 Saved 证明，再返回历史结束状态及 completion_saved。缺少证明保留 Unknown；未找到 intent 返回 not_found_is_not_proof。查询不调用 tick、不发布开始/取消请求、不执行硬件操作。

现有父会话视图补充 request_key_sha256 与独立试连/保存能力；能力只有当前 Ready 且无保存占用时开放。原试连、保存、取消的 Owner、最近登录、电话空闲及 Root 权限边界保持。
