## 本阶段行为

- `tools/system/setup_ap_install.py` 先用独立可信公钥验证七文件 AP 维护包；要求已确认的完整格式 2 应用组与包中的 Core、Edge 字节及源码一致。旧版应用、候选未确认、恢复预算已用、账号冲突、监听冲突或缺少备份均拒绝。没有绕过版本检查的开关。
- 本维护流程只接受已有一个已验证所有者的设备；首次出厂认领走既有首配流程，不能用此脚本重开认领窗口。绑定设备启动 ID、现有应用及账本、账号、服务文件、设备身份、认领已用标记和原配置摘要。
- 输出固定 27 文件及 `SHA256SUMS`，仅在维护端私有目录产生。调用者必须经固定可信 SSH 传送，并在执行前核对脚本摘要，再传入可信的整个校验清单摘要。脚本不把包内自带公钥当成信任来源；独立签名在维护端验证。没有新增网页 Root、任意 shell、AT 或 QMI 接口。
- `firmware/system/setup-ap/install.sh` 提供只读 `--check`、有限 `--apply` 和精确 `--rollback`。所有目标、UID/GID、模式和准备命令固定。写入前要求业务服务无进程/控制进程/排队任务、普通蜂窝数据断开、实际通话空闲、无未完成配网事务；不自行停服务或改网络。
- 安装先准备 Root 程序和普通材料，再以实际非 Root Core/Edge 身份执行离线准备命令。Core 仅导出既有身份绑定，不生成新认领码；Root 导入同一绑定和 Edge 证书。身份、已用标记及既有认领码快照必须保持，最后才发布 Core 和应用目标的两个接线文件。
- 已落盘的同一操作允许精确重试。已有目标或暂存文件必须逐项匹配本包，全部检查通过后才继续。遇到被改动的文件、链接或仍未确认的配网状态直接拒绝，不“修好”陌生状态。
- 回退先核对所有七个目标与暂存文件，再删除本轮匹配的文件；不自动恢复业务数据库、回收账号或重新生成凭据。私有配网材料、绑定元数据和日志目录保留。没有服务启动、`daemon-reload`、自动启用、普通 APN、信任库、分区或关机操作。

## 验证及边界

准入和打包测试使用明确标注的合成 ELF/构建元数据，签名验证是真实 Ed25519 和外部公钥。拒绝分支覆盖旧格式/跨源码或跨字节、未确认应用、身份别名及多余组成员、监听冲突（包括 IPv4 映射 IPv6）、活动业务、缺少备份、篡改与链接。没有将合成 ELF 称为实际编译的固件。

另一个测试程序在一次性 Linux chroot 中**执行实际安装脚本和真实 Native Core/Edge/AP 离线准备 CLI**，以真实 UID/GID 和文件权限验证以下九项：

1. 只读检查不改变目标文件，错误的可信清单摘要不产生写入。
2. 正常准备、重复准备保持私有材料，精确回退保留真实所有者数据库全部表和业务哨兵文件。
3. 在 Edge 准备阶段注入中断，两个激活接线文件不发布；同一操作重试成功，绑定保持。
4. 最后一个目标被改动时，回退不会先删前面的目标。
5. 活动业务、活动通话、普通数据连接及未完成 Root 配网事务拒绝。
6. 陌生链接和额外隐藏交付文件拒绝。
7. 在首次 begin 之后、目标父目录尚未建立时也可回退。
8. 硬链接暂存或设备身份变化时，在改变安装目标前拒绝。
9. 排队中的服务任务、格式错误或包含命令文本的通话返回不被当作空闲证据，也不会执行返回内容。

chroot **不暴露真实设备或网络**；PID1、进程枚举、基带和联网状态是显式夹具，`/dev/null` 是接收丢弃诊断的普通文件并从目标快照排除。Native 安装执行使用测试内独立构造的可信交付，不通过生产 AArch64 包准入；生产生成器没有此例外。不能将本测试称为真实 systemd 运行权限、实际无线切换、ARM 安装或冷启动验收。

隔离夹具开发中的动态加载器模式、空设备模拟失败均保留在私有记录；最终轮次重新运行完整受影响检查。旧 P4R 的实际 ARM64 签名包仍是独立证据，未冒充本轮新编译。
