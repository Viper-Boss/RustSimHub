# 负责人实机验收现场包

日期 2026-10-28。负责人保留的 65 项动作中，大部分卡在真人观察、真实棒子、换卡、第二设备或外发授权上。本目录把这些动作按“一次准备能覆盖几项”分成若干**现场**，每个现场写清：前置条件、门禁、逐步操作、只读检查、通过判据、证据模板和退出步骤。

**本目录只是材料，不是验收结果。** 编写这些材料时没有操作设备，也没有新增通信。每个现场实际执行时，按 [AGENTS.md](../../AGENTS.md) 逐项取得授权，结果写成独立的 `VALIDATION-*.md`，再用 `tools/progress/update.py` 记录。

## 所有现场共用的门禁

1. **唯一控制者**：现场开始前，确认设备上没有旧 `nassimhub-agent` 在运行（只读快照里应为 `inactive` 或 `unknown`）。新系统不安装旧业务控制器；如果发现它是 active，立即停止，先查明原因。旧控制器的孤儿通话策略会挂断 Rust 的通话。
2. **设备操作先只读**：每个现场都先跑一次只读快照，确认起点状态，再进入任何写操作。不写基带/NV/校准分区，不刷机，不改分区。
3. **普通蜂窝数据保持关闭**：除换卡场外，所有现场都要求 `gsm` 设备保持 `disconnected`；不开 APN，不让 Wi-Fi/USB 失败时隐式回退到蜂窝。不要为了停数据而关闭电话需要的 WWAN/IMS。
4. **通信授权**：拨打 10010 已持续授权，但必须短时、自动挂断、记录次数，结果 Unknown 时先核验、不自动重拨。其他号码、新的短信发送、Bark/转发外发，都要逐次单独授权。来电测试中，第二部手机由你本人拨入。
5. **PMIC/关机继续搁置**：任何现场都不做关机、PMIC 或断电试验，除非你另外明确安排。
6. **隐私**：快照脚本不输出号码。现场原始记录（时间线、截图、日志）放 `.private/`，公开的 `VALIDATION-*.md` 只写脱敏结论。

## 只读快照工具

[`tools/field/rsh-readonly-snapshot.sh`](../../tools/field/rsh-readonly-snapshot.sh) 在设备上以只读方式汇总：

- 相关服务的 `is-active` 状态（包括旧 `nassimhub-agent`）；
- ModemManager 当前呼叫，只输出编号、方向、状态和原因，**不输出号码**；
- 所有 PCM 子设备的状态（`closed` / `RUNNING` 等）；
- NetworkManager 设备状态；
- 指示灯：三通道亮度（`rgb=`）、trigger、灯控模式、安装是否完成，以及两个灯控输入文件里的布尔值（不输出其他字段）。

```sh
rsh-readonly-snapshot.sh once          # 一次快照
rsh-readonly-snapshot.sh watch 300     # 最多 900 秒，只在状态变化时输出
rsh-readonly-snapshot.sh led-trace 60  # 最多 120 秒，约 20 毫秒采样，只记录灯色变化
```

它不会拨号、接听、挂断、发短信、写 sysfs、改服务或网络，也不读任何凭据。
[`tools/field/test_readonly_snapshot.py`](../../tools/field/test_readonly_snapshot.py) 用桩命令实际运行这个脚本，断言所有外部调用都在只读白名单内，且号码不会出现在输出中。
脚本通过既有维护通道上传并以 Root 运行（读取呼叫和 PCM 需要 Root）。上传本身也是一次设备写入，每次现场开始前要说明并取得同意。

## 证据模板

每个现场结束后，按下面的结构写 `docs/VALIDATION-<现场>-<日期>.md`：

```text
日期/时区：
设备软件版本（confirmed 组 / epoch）：
参与者：负责人 / 你本人 / 第二部手机（不写号码）
授权：本次授权的目标、次数、范围（引用聊天中的原话或日期）
起点快照：services / calls / pcm / net 的要点
逐步记录：每一步的时间、操作、页面提示、快照变化、人的观察（听到/没听到）
判据对照：动作 ID → 通过 / 未通过 / 未执行，附依据
终点快照：与起点对比，PCM 全部 closed、无残留呼叫、gsm 仍 disconnected
异常与未知：原样记录，不改写成成功或失败
私有原始材料：.private/ 下的目录名（不放内容）
```
