# P3N 通话期间签名会话续期

更新：2026-10-24。源码及离线验证完成，尚未固定ARM/Native构建、交付或真实长通话验收。现场仍为4350895/confirmed37，整体79.5%，10010累计44。

## 问题与行为

日常电话会续租30秒的通话控制权，但登录会话原本固定15分钟失效。只续租电话不能维持登录；原网页重新登录又会停止声音和清空本地租约。因此需要独立的、可验证的登录续期。

新增签名续期：只有当前未过期的登录凭证和同一浏览器私钥一起证明身份，才签发新的15分钟凭证。旧凭证保持原期限，为在途HTTP请求提供短暂重叠；不延长旧凭证寿命。新凭证继承原身份、权限、代次和最初手动登录时间，敏感管理仍受最近5分钟登录要求约束。

网页只在日常电话动作或已确认控制的通话期间检查续期。剩余3分钟时发起一次验证，同一时刻只有一笔；空闲页面不自动延长登录。超时、失去确认、撤销或退出后停止，不自动重试，也不自动拨号、接听或恢复旧通话。

## 协议与权限边界

- `session_challenge`：输入当前token，返回现有格式的设备签名挑战；独立purpose为`session_renew`，额外绑定该token的SHA-256摘要。
- `renew_session`：输入原token、challenge_id和客户端签名；Core检查一次性挑战、原token尚有效、密钥、角色、权限及代次一致，返回新的短期token。
- 原token和新token都只存在进程内存，续期不写业务数据库、不改变schema6、不新增系统或硬件权限。会话表仍最多64项，失效会话正常清理。
- 续期不会更新`authenticated`，不会刷新所有者短信删除、配对、网络管理等敏感操作的新鲜度；需要时仍由用户明确重新登录。
- 不接受客户端时间或时长；服务端期限仍为15分钟，通话租约仍为30秒。过期凭证不能凭持有私钥在续期接口复活，需走正常登录。

Rust客户端和浏览器均先验证设备签名、公钥、角色、权限、代次、用途与原会话摘要，再签确切挑战字节。普通登录证明不能用于续期，续期证明也不能成为新的手动登录。

## 声音连续性

Core的媒体绑定由身份、代次、设备实例、线路、呼叫对象和租约代次决定；不依赖某个短期token字符串。网页成功轮换后更新内存中的请求凭证和AudioLink认证上下文，保持原PeerConnection、麦克风轨道、媒体session及通话租约。

正在预连接的声音也同步更新凭证，避免接通时因凭证变化重新握手。已经发送的旧凭证请求可在原有效期内完成；下一笔请求使用新凭证。续期不再激活PCM、不发新媒体票据，不放松现有服务端媒体授权。

客户端根据续期请求开始时间保守计算期限，整轮验证最多45秒；停止或替换登录会取消等待。网络过慢或认证失败时关闭声音、停止续租，由现有核心租约清理；不能据此宣称恶劣网络下通话不间断。
