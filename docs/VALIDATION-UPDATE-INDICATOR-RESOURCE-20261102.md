# 升级灯效线程耗尽：主线代码修复

## 问题与改动

更新器的 `Activity::begin()` 在初次写入“升级中”后使用 `std::thread::spawn`。操作系统无法再创建线程时，该函数会 panic；发布配置又使用 `panic = "abort"`，因此辅助灯效可能直接中断已通过前置检查的更新命令。`stage`、`admit-stage`、`choose` 使用该守卫。

现在改为 `thread::Builder::spawn` 并处理创建失败：尽力写回 `upgrading=false`，返回不启动线程的守卫，使调用者可以继续执行。若撤销写入也失败，既有十秒提示有效期仍保留。正常三秒续期、退出时停止并撤销提示的行为不变。未修改签名、账本格式、维护授权、更新锁、回退或业务数据策略；这不代表资源耗尽时更新的其他必需步骤也一定能成功。
