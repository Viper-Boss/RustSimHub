# 短信候选关联的人工核对

2026-10-23，整体暂保持78%。本项补齐候选展示和核对入口，不改变后台的消息身份判定，不把同内容记录自动合并。

## 实现

收件箱带有 `duplicate_candidate` 的摘要显示“可能重复，待核对”。打开详情时先清理旧选中项，只有本次请求仍属于当前列表/当前详情时才选中新记录；等待另一条短信详情时旧删除按钮和比较面板立即清空。

候选面板并排展示当前记录和候选旧记录的ID、线路代次、号码、原时间、正文及二进制长度/十六进制数据。点击才查询旧记录；普通读取失败不自动切换到所有者回收站接口。所有者可以再手动选择从回收站读取旧记录，失去所有者权限时清理已读取的回收站正文及在途回复。候选响应的记录ID、正文/数据形状与长度均有界检查，使用textContent呈现。

比较只发送 `sms_detail` 或用户明确选择的 `deleted_sms_detail`，不标记旧记录已读，不创建删除/恢复/合并动作，不自动跟随候选链。实际本地删除继续使用原所有者最近登录、确认、tombstone和事件同步接口；按钮只针对当前记录，原件保持现有状态。普通客户端无法由比较入口获得回收站权限。二进制内容及同内容真实新来信都保留。

SIM指纹和content_hash只在后台决定“候选”；线路和对象经历重启后无法证明相同物理短信，故不恢复或猜测旧对象身份。没有数据库DDL或schema变化，保持schema6。

## 已完成检查

七组网页回归通过。其中短信管理测试直接加载生产模块，新增正常只读比较、无隐式回收站重试、所有者回收站读取、无权请求拒绝、自引用/非法关联、错ID/超限/错误二进制拒绝、换选/注销/撤销/确认删除后的迟到回复隔离、旧请求结束不释放新请求，以及二进制显示。

真实app.js夹具新增从收件箱候选标识→详情→手动比较→注销清空的串联，并验证读取新详情前清空旧选中项、没有意外删除或恢复请求。旧有身份、媒体、拨号、防重、网络、事件和回收站回归均通过。

尚需实际浏览器布局、固定提交构建、签名组升级和正式页面读取验收；本页不将离线检查说成已交付。不改既有Owner身份、已消费的首次设置窗口或现场短信原文。
