# AirSIM 实机无声：阶段诊断交付

## 当前结论

应用 79 的网页自动显示配对记录已由用户确认通过。随后一次人工 AirSIM / VoWLAN 10010 测试，用户反馈接通后没有声音，并已手动挂断。当前不能将 AirSIM 双向音频标为验收通过。

只读观测覆盖了真实通话：通话状态曾为 ACTIVE，手机到 PCM 端口的 TCP 连接存在，但所有被采样的 ALSA 状态均为 closed，原生音频服务没有留下会话启动或关闭统计。观测中出现两个新的拨出对象；仅凭对象数不能推断客户端自动重拨。代理没有自动拨号或保存录音。

已核对媒体工作器路径、套接字与父目录权限，未发现配置不匹配。现有证据把问题缩小到声卡打开前的链路，但不能确定握手、授权、状态观察、时限或本地工作器接线中的哪一步失败。

## 本次改动

- Edge 为每个 PCM 连接记下一条固定阶段名和总耗时，覆盖预握手、Core 打开、等待 ACTIVE、清理接通前数据和本地工作器连接。
- Edge 只在 Core 调用失败时记录固定操作名、超时或不可用/拒绝分类及耗时；不把“不可用或拒绝”冒称为鉴权错误。
- Core 在原有拒绝点记录固定阶段，区分没有本机拥有的通话、其他所有者、通话观察、媒体租约和媒体授权等失败。
- 日志不包含地址、配对记录 ID、签名、密钥、票据、会话 ID、请求正文或音频。streaming 标签只表示进入传输逻辑，不代表真实声音已通过。

本次只补诊断，不调整协议、权限、单会话限制、租约、700ms Core 调用预算、60ms 帧龄或原有关闭行为。没有通过延长超时或放宽授权掩盖问题。

## 已运行验证

```sh
cargo +1.98.0 fmt --all
cargo +1.98.0 test -p rustsimhub-core --all-features pcm_ --locked --offline -j8
cargo +1.98.0 test -p rustsimhub-edge --all-features airsim --locked --offline -j8
cargo +1.98.0 clippy -p rustsimhub-core -p rustsimhub-edge -p rustsimhub-wire --all-features --all-targets --locked --offline -j8 -- -D warnings
```

结果：Core 5 项、Edge 15 项通过，严格 Clippy 通过。其余测试被筛选，不能计为已运行。该轮使用开发用来源标记，不是可安装制品。

固定提交的全量测试、ARM 构建、原生工作器同源验证、签名与部署尚需另行记录；本文件不宣称已执行。完整原始观测和构建日志只保存在负责人的私有证据目录。
