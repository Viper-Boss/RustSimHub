## Reproduced failure and change

The actual original Root tests were built with Rust 1.98.0 on a new Debian 13
guest, Linux 6.12.117. In a private systemd temporary filesystem, chmod followed
by restoring permissions after the original 2 ms delay retained the exact same
ctime. A separate real-file probe printed identical before/after nanoseconds;
a later mutation after 20 ms recorded a different timestamp. The original
`readonly_running_fd_guard_rejects_replacement_restored_metadata_and_parent_alias`
failed at `mode`, and `held_sources_reject_mutation_replacement_and_extra_materials`
failed at `manifest`. These failures remain in the original logs.

Four Rust test files change. A shared test helper repeats the actual chmod or
same-byte signed-manifest rewrite until metadata confirms a different ctime,
with a one-second monotonic deadline. Missing observable change panics; it is
never a skip or success. Both original rejection assertions remain. No
production implementation, signature/domain, target table, role/UID, health
interface, permission budget, workspace dependency, lock or boot policy changes.

This establishes the tests' timestamp precondition. It does **not** make ctime
an audit log or promise detection of every same-byte/permission restoration
within one filesystem clock tick. The unchanged guards compare held/named
objects, bytes and metadata; this PR does not strengthen that production
contract. The fixture must not be cited as proof of such a stronger property.
