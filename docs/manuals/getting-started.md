## 打开前的准备

向负责人取得与你这台设备对应的网页地址、可信证书交付办法，以及用于核对的设备公钥。
网页地址和设备公钥需要通过可信渠道核实；出现证书或身份不匹配时先停止操作，交负责人核对。
不要关闭证书验证，也不要仅凭页面显示的公钥决定信任。
已有首次正式认领及严格 HTTPS 核验记录，范围见[证据 S01](support-evidence.md#s01)。

首次设置或新浏览器需要保存浏览器身份的能力；使用你计划长期保留的正常浏览器配置。
页面使用浏览器持久存储保管钥匙及操作记录。清除网站数据、重装浏览器或更换浏览器配置可能丢失这些材料；
如果这是所有者浏览器，先向负责人确认恢复安排。[身份保存的实现与验证](support-evidence.md#s01)

## 已经认领过的设备

1. 打开负责人交付的地址，核实连接与设备身份。
2. 使用原来获准的浏览器，点击日常页面的“登录”；在“连接与配对设置”中对应入口为“登录已批准的浏览器”。
3. 登录成功后先点首页“检查状态”，阅读提示；暂不进行拨号或发短信。
4. 后续按[日常使用](daily-use.md)选择短信或电话区。

如果浏览器尚未获准，登录失败不会自动把它变成所有者。
不要重跑初始化、删除设置标记或清空数据库来“重新认领”。
[登录、认领和配对范围](support-evidence.md#s01)

## 负责人安排的首次认领

本节仅适用于负责人明确交付的临时设置码流程。新版开放热点/用户名密码首配是另一条流程；
不要将本节套到没有设置码输入的页面，先向负责人取得该版本的首配指引。
仅当负责人已经完成设备准备、明确开启首次设置并提供本次临时设置码时，才进行本节。

1. 展开“连接与配对设置”，将“设备公钥”与负责人通过可信渠道提供的值逐字核对。
2. 在“首次设置”中输入本次临时设置码，点击“初始化第一个所有者”一次。
3. 等待结果；成功后页面进入正常登录流程，妥善保留这个浏览器的身份。
4. 若页面说“首次设置结果尚未确认”，先尝试正常登录并联系负责人，不重复初始化。

已认领、窗口关闭或设置码失效时，不应通过刷新、改文件或换设备身份重新开启首次认领。
这套流程已有一次正式认领验收；它不证明所有首次热点配网路径都已通过。
[首次认领与热点边界](support-evidence.md#s01)、[配网范围](support-evidence.md#s12)

## 新增另一台电脑或浏览器

在新浏览器的“连接与配对设置”核对设备公钥，再按需要选择权限并点击“申请配对”。
将页面显示的浏览器公钥、申请编号和所申请权限交所有者核对；申请成功不等于已经批准。
批准后使用“登录已批准的浏览器”。所有者批准入口及最终权限以负责人交付版本为准。
不要把设置码、会话凭据或原浏览器钥匙发给其他人代为登录。
[配对实现及验收限制](support-evidence.md#s01)

## 登录与退出

登录成功不代表同时拥有所有操作权限。普通读取、短信发送、电话控制及所有者管理有各自边界。
回收站修改、部分网络设置要求所有者最近五分钟内登录；可读短信不等于可删除短信。
遇到管理资格提示，使用对应的重新登录按钮，再核对目标记录。
仍拒绝时按[权限错误](troubleshooting.md)处理，不连续尝试写入。
[所有者管理证据](support-evidence.md#s06)

退出会使当前页面的登录和声音操作失效，但不能撤回已发出的短信，也不能作为电话已经结束的证明。
有未确认操作时保留原浏览器记录，重新登录后查询同一笔操作。
[操作与声音边界](support-evidence.md#s05)、[日常电话](support-evidence.md#s08)
