## 过程与结果

- **本地回归**（代替 CI）：fmt、整仓严格 Clippy 通过；整仓测试 645 通过、7 失败，失败项和应用 51/52 时相同，都是已知的 WSL 环境问题（5 项转发出口测试需要网络绑定，2 项 compat 测试缺 Go）；网页测试 16/16；进度工具测试通过。WSL 里的 git 读不了 Windows 工作树的版本信息，所以测试源码的版本改用 Windows 端的 git 核对。
- **构建与签名**：ARM 程序 11 个；原生音频组件在 QEMU 上通过 33 项 ARM 测试；签名为格式 2 的 6 文件应用组（约 22 MB），签名密钥与设备现有信任一致；用真实 ARM 更新器验签通过，3 个反例都被拒绝。
- **设备操作**：只读预检 → 上传并在设备上验证（不安装）→ 停机持锁业务备份（数据库完整性通过，旧应用组已恢复运行）→ 暂存并回读 → 选择启动一次 → 健康检查 → 确认。
- **结果**：floor 和 confirmed 都是 53；14 个 HTTPS 资源与源码逐字节一致；身份和所有者、95 条短信、未知回执不变；音频 7/7；转发关闭，已保存的 Bark 配置保留；普通蜂窝数据关闭；出厂档位 16 和自动恢复预算都没有动用。

## 中途失败（保留记录）

第一次暂存时，脚本用 Windows 默认的 GBK 编码读取 UTF-8 写的备份记录，含中文的本机备份路径被解错，读不到 `updater-before`。失败发生在设备只读核对之后、任何写入之前，记录中 `stage_attempted=false`，已改名为 `*.failed-encoding` 保留。启动脚本因为同一原因，在读取本地记录时就失败了，没有连接设备。改用 `PYTHONUTF8=1` 后重跑，暂存、启动、确认都一次通过。
