# X1M：有限转发安装器与文件回退

2026-10-25，源码/本机验证阶段。承接 [X1L实机应用组](VALIDATION-FORWARDING-DEVICE-X1L.md)：棒子已确认epoch47，但本记录建立时转发账户、Root单元和Core管理通道尚未安装。原P0–P7保持80%，扩展单列。

`tools/system/forwarding_install.py`在维护电脑上检查私有现场清单，生成固定九个文件的可审查安装包。棒子执行包内POSIX脚本，不安装Python。首版只接受已实际验证的epoch47/固定源码与manifest；不把任意六文件包都当作兼容管理参数的应用。继续使用设备已有签名信任，不新增发行密钥。

## 安装和回退边界

- 清单同时检查本地及NSS解析的passwd/group，拒绝UID/GID983占用、数字别名、已有同名账户、其他用户把服务组用作主组、残余附加组成员。固定Core/Edge/Media与IPC身份必须匹配。
- 只接受精确已确认基线、无待处理应用、原Core启动参数、支持credential的systemd、空闲呼叫/PCM、普通数据关闭和已回读的一致性备份。文件目的地及转发目录必须全部不存在；不能重复运行来“修理”已有安装。
- 包内含业务备份的相同字节、固定目标映射、摘要与计划。设备端重验包文件类型/权限/硬链接/摘要、boot ID、实际选中manifest、台账、原Core单元和账户文件摘要。`--check`只读，不创建锁文件。
- `--apply`要求整个应用组已停止，持有限维护锁；先完成全部冲突检查，再创建锁定的983服务身份及IPC附加组，创建有限目录并逐文件原子发布。最后才发布Core管理参数。脚本不启动服务、不创建enabled标记/凭据、不扫描或恢复业务数据库。
- `--rollback`只在整组及转发服务均无进程、无启用标记/凭据时允许。先核验**所有**已存在目标的精确权限及字节摘要，任何一项变化就全部保留，待人工核对；通过后仅删除这九个固定文件。锁定账户、目录和业务数据保留，不自动删除/重分配账户、不回滚短信状态。
- 账户创建中途失败会留下需显式核对的未使用身份；这不是可自动恢复任意Root安装失败的事务引擎。现场启停、daemon-reload与有界恢复计时器由维护流程负责，不能把文件安装通过当成已启用业务或冷启动通过。
