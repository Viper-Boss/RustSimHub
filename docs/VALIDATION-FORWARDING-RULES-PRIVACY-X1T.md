## 行为与接口

规则保留发送方完全匹配、正文包含、SIM 代次和最多8个目标的多选组，新增可选 `conditions`。所有非空条件按 AND 匹配；同一目标只使用第一条匹配规则，防止重叠规则重复递送。默认只转发之后的新短信通知，二进制和疑似重复候选不匹配；不新增历史补发、自动重试或外部测试发送。

```json
{
  "conditions": {
    "body_regex": "验证码[A-Z0-9]{6}",
    "time_window": {
      "start_minute": 1320,
      "end_minute": 360,
      "utc_offset_minutes": 480
    }
  },
  "share": "masked_text"
}
```

例子表示中国固定UTC+8的22:00（含）到06:00（不含），按短信标注的RFC3339时间换算；不使用读取积压短信时的设备当前时间。不自动处理夏令时；缺少/无效时间时不匹配时间条件。全天不限请关闭时间条件，起止相同会拒绝。

| 模式 | 实际外发范围 |
|---|---|
| `notice`，默认 | 固定新短信通知；不附原始发送方、正文或短信时间 |
| `masked_text`，明确选择 | 正文中的ASCII英文字母和Unicode数字字符逐字符替换为星号；不附原始发送方和时间。中文、空格和标点保留 |
| `full_text`，明确选择及保存确认 | 原始发送方、时间和完整正文；原有显式授权行为保留 |

隐藏英数字是确定的字符替换，不是通用验证码/个人信息识别器；其他语言字母或中文敏感内容仍可能保留。对敏感短信使用默认仅通知。Webhook、Bark、Telegram使用各自实际编码器；Telegram的长度回退也只取本模式的安全正文，不能回退到未脱敏原文。合成测试仍只发送内置固定文本，本轮没有执行真实通知。

## 有界开销与缓存

- 模式固定 `regex-lite = 0.1.9`，最长256个UTF-8字节、编译程序最多8192字节、嵌套16层；不支持环视、反向引用或Unicode属性。消息正文最多4096字节、最多32条规则，只有单次 `is_match`，不进行全量匹配迭代或JS正则执行。
- 上游给出的单次匹配界限与编译大小限制见[regex-lite文档](https://docs.rs/regex-lite/latest/regex_lite/)。新依赖已锁定校验和 `cab834c73d247e67f4fae452806d17d3c7501756d98c8808d7c9c7aa7d18f973`，未升级其他锁定依赖；复用已有 `time 0.3.55` 解析时间，避免自写日期解析器。
- 每个Queue只缓存当前策略及编译结果；查询仍读取并校验数据库策略字节的SHA-256和状态。修改提交后立即丢弃旧缓存，损坏数据不能因缓存命中被忽略。显式配置写入时才建立独立策略所有权，临时序列化缓冲区会清零；没有新增轮询、线程或常驻进程。
- 新库选择其MIT许可，原文保留在[许可文件](../licenses/regex-lite-0.1.9-MIT.txt)；不把依赖代码算作本项目原创。

## 旧客户端、身份与持久化边界

Core状态发布 `rules_revision=2`。编辑请求 `PolicyEdit.rules_revision` 在原有简单规则上可省略；若旧或新策略含扩展筛选/脱敏模式，必须明确为2，其他版本拒绝。旧页面因此不能在忽略新字段后把受限规则保存成宽泛规则；新版页面完整回读、保留和编辑这些字段，未知条件也拒绝编辑。

不改变Owner最近登录、scope、设备/SIM代次或递送前的实时鉴权。扩展规则先校验再创建/修改状态；失败不推进配置代次、游标或回执。普通旧策略的JSON不增加空 `conditions` 字段，现有数据库格式和出站请求格式保持。旧程序遇到新策略的未知模式/字段会拒绝读取；应用回退兼容仍归FWD-20独立验收，不能由本次源码通过推定。
