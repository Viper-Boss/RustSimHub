# NKN 安装统计签到集成

日期 2026-11-21。应用实现固定在 a38bccbbdd88e000882d65c1ef169269fd4bc52c。以已部署 97 版的控制台源码、98 候选的查询备用节点及 PR 268 的固定受管事务实现为基础，在独立分支整合。

## 实际行为

- 设备准备独立随机的统计身份，私有种子保留在 Core 状态目录；初始化入口只输出公钥，禁止用 root 用户初始化和覆盖已有身份。
- 所有者可继续单独读取和保存参与授权。设备拥有匹配的受管配置、身份和 Root 套接字，并确认当前所有者已经授权时，页面显示「签到或核对」。一次调用只提交一笔或核对原待确认摘要。一笔结果不明时会保留，后续不会重发或转到下一窗口。
- 主网 nonce 允许已实测的 currentHeight 字段。确认采用官方 HTTPS 交易索引提供的高度提示，以及固定官方钱包 API 返回的区块交易列表；核对原摘要、至少六个后续区块、两次读取区块的哈希一致。节点接收回执、交易池、索引单方结果、区块过浅或不一致均无法确认。
- 查询卡片仍国内节点优先，再走官方 HTTPS 和八个备用节点。交易确认使用固定 HTTPS 端点。定时续订和长期网络授权没有打开。

## 已验证

- 真实公开主网接口只读探测了 nonce、历史订阅摘要、包含该摘要的区块、当前区块高度及 WebSocket 路由。没有使用设备统计公钥进行公网查询，也没有发起真实交易。
- Core NKN 专项 30 项库测试和 9 项 bin 测试通过，另有原有 5 项隔离夹具未运行。产品依赖特性组合的严格 Clippy 通过。单独启用签到 feature 的全目标 Clippy 中，原转发测试有 4 处无用转换警告。Edge 75、Wire 30、网页统计、参与授权和蓝牙模式专项通过。
- 已验证模块缓存上的 Go 测试通过，包括真实 SDK 特性以及错摘要、浅区块、同高不同块和离线等否定场景。固定 Go Root 和 SDK ARM 链接、QEMU SDK 元数据均通过。
- Core/Edge/Forwarder/更新器 ARM 已构建。应用载荷的初次构建超限，只对 Core 使用面向体积的编译选项后为 24,759,441 字节，低于现有 25,165,824 字节上限。实际 ARM Core 在 QEMU 临时目录下复验了产品模式、非 root 初始化、0600 文件、重复请求拒绝及原身份保持。
