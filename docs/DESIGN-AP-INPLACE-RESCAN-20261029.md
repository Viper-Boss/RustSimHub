# 热点内重新扫描：分阶段实现与交接

日期：2026-10-29。仅主线负责人范围；D任务继续暂停，其他成员接口和分工不变。

**当前只有暂停/扫描/恢复后端与事务完成，保护RPC、持久回执、Core和网页尚未接入。没有新按钮，也没有启用新硬件操作。** 此工作在独立`codex/ap-rescan-20261029`草稿分支，基于PR #65，不混入应用70的固定来源。70仍是[开热点前扫描候选](VALIDATION-AP-ACTIVE-SCAN-20261029.md)，本批不在它的二进制里。设备保持已确认69，用户此前不方便测试，本轮不切网、不开热点。

## 目标和用户动作

用户在热点页点击一次“重新扫描”，明确知道热点会短暂断开；设备完成一次扫描并恢复原热点。手机重新接入后，原页自动只读查询同一操作。成功显示新的SSID列表及实际快照年龄；空结果保持为空，不用旧SSID伪装成功。失败且已恢复时说明失败；不确定时保留操作编号，只查询，不重发扫描、不猜测保存成功。

“读取本轮列表”继续是只读动作。20秒自动读取不能隐式触发新扫描。首次开热点前的主动扫描与热点内显式重扫是两条有共同扫描收集器、但不同网络恢复边界的流程。

## 已实现的后端

| 位置 | 动作与边界 |
|---|---|
| `ap_rescan.rs` | `RescanProvider`只给出借用本轮私有AP的会话；`RescanNetwork`只有pause/scan/restore，无SSID、路径、命令、APN或保存输入。调用者必须先持久消费受认证的唯一请求。 |
| `ap_rescan::run` | 工作窗口至多20秒且初始租约/隔离检查计入原截止时间；扫描前后复核Gate和父隔离；工作失败、超时、取消后仍等待最多8秒精确恢复。恢复或隔离无法证明则Unknown，不释放父隔离。结果`ScannedAndRestored`只证明无线/原AP恢复，**不证明HTTPS或用户页面已经可用**。 |
| `nm/refresh.rs` | 只允许保留在RAM中的自有AP，先核对原父检查点、私有AP、原连接集合及蜂窝不自动连接。为固定wlan0创建45秒自动回滚的内层检查点，再验证真实活动连接属于本轮私有AP后调用DeactivateConnection，不停USB/蜂窝/原保存连接。 |
| `nm/scan.rs` | 复用有界扫描收集器，新增“暂停后的AP”内部上下文；允许且仅允许原父+本次内层检查点。固定设备/唯一NM进程、无线/接口状态、LastScan与LastSeen复核保持，单次扫描至多8秒。 |
| `nm/refresh.rs` | 单个会话最多一次暂停和扫描，丢回复/超时也不重试。只通过精确内层CheckpointRollback恢复，不用ActivateConnection盲目重启AP；兼容回滚消耗或保留检查点，保留时仅销毁自己已知的内层检查点。 |
| 恢复不明 | 保留refresh标记，禁止父事务直接回滚、试连和保存。重新取得会话只能清理，不能再暂停/扫描；回滚/销毁回复丢失时，不再次执行写操作。之后只有在已知检查点消失、原AP及连接集合完整时，才能只读证明恢复并清标记。 |

45秒是NM的有界自动回滚尝试，**不是崩溃后必定恢复网页的保证**。进程崩溃、NM更换、外来检查点或AP未恢复都不能写成成功。后续RPC层还必须保持Root持久Unknown和父隔离，提供只读回执与受控维护路径。

当前生产执行器没有调用`ap_rescan::run`，没有消费重扫请求槽，Core也没有新命令；所以新模块不能通过现有网页触发。不新增依赖，不改安装契约、系统服务、签名信任、固件分区或量产版本。

## 接下来必须实现的接口与动作（草案，均未实现）

### Root保护通道和执行器：9个动作

1. 增加固定请求、结果、只读查询槽；只读软件能力信号放独立固定槽，避免让旧Core因原Availability增加未知字段而失效。缺少能力信号按“不支持”处理，不因为新应用已构建就声称Root已支持。
2. Request仅有format、原Binding、scan_id、Owner公钥摘要/代次、请求时间/截止和有限Scan/Cancel动作。UUID、完整Binding、当前boot、请求新鲜度和原截止必须严格核对。Scan工作最长20秒，完整请求期限最长40秒，并为父截止保留至少20秒；不得延长父窗口或调整检查点超时。
3. Root先写不可覆盖的消费intent和active标记，再确认接收；同一scan_id同一完整请求只能读回执，改变Owner/请求体/父轮次必须拒绝。每父轮最多8次、至少30秒间隔；全局目录仍有文件数上限。
4. 拒绝与未确认试连、保存、另一次重扫重叠。未被Root消费的其他动作不能因文件读取顺序而一起执行。
5. 调用本批事务；期间持续写Starting和子操作状态、检查父租约和精确Cancel，收到关闭/失去授权仍等待清理，不能drop正在恢复的future。
6. 原AP恢复后再用真实readiness.ap_check核验HTTPS、复核隔离与租约，才允许Ready。完成的空扫描仍是成功空结果，不回旧列表。
7. 保护Status需绑定完整intent，有限Scanning/Ready/Failed/Unknown状态，Ready要求新Snapshot及真实AP/HTTPS恢复；Failed要求已验证恢复且无新Snapshot；Unknown不声称恢复。Root持久终态先于输出，输出丢失只重发回执。
8. 新快照只能在验证恢复和HTTPS后替换当前原Binding的保护快照；旧轮次、旧扫描、错误nonce/Owner代次、未来时间和过大/畸形数据拒绝。
9. 重启/Unknown/发布失败只读恢复持久回执，不重新暂停或扫描，不擅自释放父隔离。明确区分活进程内可只读证明的恢复与重启后缺少证据的Unknown；不能套用内存标记宣称跨重启恢复。

### Core与认证命令：8个动作

1. 有限`setup_ap_scan_begin/status/cancel`命令草案：输入仅父operation_id和scan_id，复用现有token，不接受网络接口/路径/SSID/命令。
2. Begin/Cancel要求最近登录的真实Owner及NetworkManage，前后验证身份代次/实例；配对客户端不能越权。Status只读，但仍限定原Owner及设备域。
3. 初次Owner仍按已有规则接管原AP，不新建窗口、不重置父deadline。
4. 在既有网络/通话协调锁下拒绝与试连、保存、通话、其他测试和重扫冲突；有未知操作时先核对，不清记录绕过。
5. Core先保存唯一intent再发布Root请求；Body丢回复或Core重启只查询该scan_id，不写新的Scan动作。
6. 状态只接受Root精确intent、当前boot/轮次和有界Proof；旧Root能力缺失时明确未支持，不发送无法处理的硬件请求。
7. Ready/Failed/Unknown投影分清扫描完成、AP恢复、HTTPS恢复和权威结果，绝不返回Wi-Fi凭据；Root不明结果保留，未确认操作不允许新测试。
8. 取消、Owner撤销、Core重启、父关闭、终态补同步分别覆盖；只有明确的终态可归档，不用查询按钮清理不确定intent。

### 网页和一键体验：8个动作

1. 新按钮与“读取列表”区分；点击后一次确认短暂断热点，确认前无副作用。
2. 自动登录、复用/接管本轮AP，持久保存仅设备公钥/父ID/scan_id和提交阶段，不保存密码或token。
3. 提交前固化唯一scan_id，网络断开和请求超时都只查询同一笔，不自动重发Begin。
4. 提示重连同一热点，自动轮询有界退避；重开页恢复这笔进度，不创建新的操作。
5. 只有权威Ready刷新下拉列表，空结果清空旧列表；Failed保留失败说明和旧列表的真实年龄，Unknown保留编号。
6. 热点内重扫与开始试连/保存互斥，正在恢复时不能点第二次；Cancel也不被实现为重新扫描。
7. 复制测试结果包含设备软件版本、操作ID、状态和恢复证据，不含密码/私钥/token/完整后台日志。
8. 旧Root/旧浏览器缓存、退出登录、并发页、手机captive窗口与Safari重开分别有明确提示及回归测试。真人体验仍需手机验收，模拟DOM不能替代。
