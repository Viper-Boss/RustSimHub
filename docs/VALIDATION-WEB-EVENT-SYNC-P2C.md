# P2C：网页事件补同步的分页、失败重试与退出清理

2026-10-23。用户要求先搁置关机问题、继续其他固件任务；本轮完成 R04 网页事件补同步的一个离线改进。**整体仍 76.5/100**，本项不替代新系统短信实机闭环，不重复增加既有短信功能的验收点。

## 实际问题和结果

原 `app.js` 每次只读取一页短信和一页通话事件，每页最多32条；随后先保存两个游标，再刷新相应列表。如果列表刷新失败，游标已经越过该批事件；之后再点补同步可能读到空页，列表不会因这批事件重新刷新。

现在新增独立的 `EventSync`，每次手动操作对每类事件最多追赶8页、256条。每类列表只刷新一次，成功后才保存该类游标；取页、校验或列表刷新失败都保留该类原位置，供用户再次点击重试。已完成的一类可独立保留进度，不要求另一类权限/服务也成功。达到分页上限时明确提示继续点击，不自动无限追赶。

退出登录、页面离开或手动刷新状态会清理补同步位置并使进行中的任务失效。旧任务的迟到结果不能推进新任务游标；旧任务的 finally 也不能释放新任务的并发标记。短信/通话列表分页游标在退出时同步清空。

事件页检查覆盖有界页长、十进制 i64 范围游标、严格递增的事件序号、末事件与页游标一致、同一次/同位置追赶的数据库 epoch 保持。序号使用 BigInt 比较，不将超过 JavaScript 安全整数范围的字符串转换为 Number。游标异常时保留原位置，提示刷新状态后重新开始。

该模块只使用既有 `inbox_events`、`call_events` 和列表读取接口；列表详情、短信发送、呼叫提交、会话权限、租约、数据库格式与设备控制行为均未改动。手动补同步不是后台推送，也不是首次扫描的完整历史数据下载；列表仍按既有分页展示。
