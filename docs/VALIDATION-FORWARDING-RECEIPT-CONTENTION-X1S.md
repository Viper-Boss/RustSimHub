## 问题与修正

- 原生 CI 40318741734 的真实服务夹具收到四笔预期合成 HTTP 请求，但最后一笔回执为 `unknown`，自动停止已经完成。70313db 的早前失败还包含查询被 Core 拒绝。失败记录保留，不把重跑成功当根因证明。
- 真实 Auth 锁被其他请求持有时，`Controller::passive_request` 返回 `Busy`。原一键测试任务直接传播该错误，随后执行清理；如果 worker 正在等待 HTTPS 回复，未确认任务会按设计变成 `unknown`。新增确定性测试使用真实锁，修正前失败、修正后通过；这证明该机制，不能单凭现有旧日志断言每次 CI 失败都来自同一原因。
- 现在只在原有 30 次、每次 500ms 的观察循环内重查无副作用回执；外层 30 秒预算、Root 8 秒、worker 30 秒租约、HTTPS 10 秒预算不变。鉴权失败或缺失回执仍退出并清理。发送、配置、启动动作没有自动重试，既有 `unknown` 不恢复或重发。
- Python 真实服务夹具同样只对最后的只读回执查询容忍暂时拒绝，仍须在原 20 秒内拿到 `confirmed`、自动停止证明、零进程及原 OFF 策略，才算通过；没有降低成功条件。
