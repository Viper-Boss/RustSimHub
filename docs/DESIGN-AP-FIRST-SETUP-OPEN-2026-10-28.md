# 设计草案：首次配网改为开放热点 + 自动弹出配网页（2026-10-28）

用户决定：只在**首次配网**（设备还没有管理员）时使用。已有管理员的设备重新配网保持现状：热点有密码，用 `.local` 网址和已配对的登录。

## 用户看到的流程

1. 新设备上电，没有可用 Wi-Fi 时开出无密码热点 `RustSimHub-XXXX`（XXXX 为序列号后 4 位，与之前要求的热点名一致）。
2. 手机连上后，系统自动弹出配网页（captive portal）；电脑可以直接打开 `http://192.168.100.1`，不需要 https，也不用带端口。
3. 页面列出扫描到的 Wi-Fi，也可以手动输入名称（之前要求的“选择 + 手动”两种方式）；填密码后先试连，再确认保存。
4. 保存成功后热点关闭，页面提示“请连回家里的 Wi-Fi，打开 `http(s)://rustsimhub-XXXX.local`”，在那里完成管理员设置和配对。

## 实现要点

- 只在首次配网模式启用：Root 助手判断“没有管理员、没有已保存的 Wi-Fi”，热点用 `key-mgmt none`（开放）。有管理员时继续用现在的加密热点和登录，代码路径分开，并各自测试失败路径。
- 自动弹出：NM shared 模式自带的 dnsmasq 把所有域名都解析到 192.168.100.1；在 80 端口提供一个只读的 http 小服务，对各系统的探测地址（Android `generate_204`、iOS `hotspot-detect.html`、Windows `connecttest.txt`）返回跳转，跳到配网页。
- 80 端口的配网页只提供首次配网需要的几个操作：扫描、试连、保存、查询状态。短信、电话、转发、设置等接口一律不开放。保护表（nft）在首次配网模式下只额外放行 80 端口和 DNS，其他规则不变。
- 页面不依赖浏览器存储：手机的弹出窗口经常没有持久存储，网络一变就会关掉。状态以设备回执为准，页面关掉后重新连热点，就能看到当前状态。

## 风险（用户已知并接受，仅限首次配网）

- 热点开着的时候，附近的人也能连上、看到配网页，甚至抢先提交 Wi-Fi。缓解：同一时间只接受一个进行中的配网操作；热点有时间上限；保存后立即关闭热点。
- http 不加密，填写的家庭 Wi-Fi 密码会在空中明文传输。缓解：只在首次配网的短时间窗口内使用，之后的管理全部走 https。

## 需要实机验证

- 开放热点在 wcn36xx 上能否正常工作；手机（Android/iOS）和 Windows 是否真的自动弹出配网页；弹出页里能否完成试连和保存。
- 当前这台设备已经有管理员，验证首次配网需要恢复出厂状态，或者另找一台新设备。具体方案执行前要单独请用户确认。

## 用户补充决定（2026-10-28，第二轮）

- 首次配网：连上热点后，**先设置用户名和密码**（成为管理员），再配置 Wi-Fi。不再使用一次性设置码，也不依赖浏览器配对。
- 配网页必须能**扫描附近的 Wi-Fi**，也能手动输入名称。

## 开发分段（按顺序，每段单独测试）

### 第 1 段：账号密码（认证层）
- `rustsimhub-auth` 新增“用户名 + 密码”管理员凭据：scrypt 加盐哈希（依赖已在 Cargo.lock 里），只保存哈希；用户名 1–32 个字符，密码 8–64 个字符。
- 只有设备没有管理员时才能创建（与现有“首个管理员窗口”同一把一次性锁）；创建成功后窗口关闭，不能再创建第二个。
- 用户名密码登录得到与现在相同的会话令牌（15 分钟）。连续输错有冷却：5 次后锁 60 秒，并按次数逐步加长。
- 现有浏览器密钥配对保持可用，已有管理员的设备不受影响。
- 失败路径测试：重复创建、并发创建、错误密码、冷却、哈希文件损坏或被替换、重启后状态保持。

### 第 2 段：首次配网热点（Root）
- 设备没有管理员时：热点不设密码（`key-mgmt none`），热点名 `RustSimHub-<序列号后 4 位>`；有管理员时保持加密热点。是否开放由 Core 的首个管理员窗口决定，Root 再独立核对一次（核对不通过就开加密热点，不会意外开放）。
- 扫描：wcn36xx 只有一个射频，开热点时大概率不能同时扫描。因此开热点前先扫描一次，把结果（名称、信号、加密方式；不含密码）交给配网页；页面上的“重新扫描”需要短暂关闭热点，**能否在热点模式下扫描要实机确认**。
- 失败路径测试：开放与加密两种热点配置的读回校验、管理员状态变化时拒绝、扫描结果的大小和数量上限。

### 第 3 段：自动弹出与 http 配网页
- NM 共享模式的 dnsmasq 增加只对热点生效的配置：所有域名都解析到 192.168.100.1。
- 配网用的 edge 增加 80 端口 http，只在首次配网模式下开放，只提供：创建管理员、扫描结果、试连、保存、查询状态。对各系统的联网探测地址返回跳转，让系统自动弹出配网页。
- 保护表在首次配网模式下只额外放行 80 端口和 DNS。
- 失败路径测试：已有管理员时 80 端口不开放；非配网接口返回 404；超大请求或慢速连接有上限。

### 第 4 段：网页
- 弹出页流程：设置用户名密码 → 选择或输入 Wi-Fi → 试连 → 保存 → 提示连回家里的 Wi-Fi，打开 `rustsimhub-XXXX.local` 用用户名密码登录。
- 日常网页增加用户名密码登录（与现有配对登录并存）。

## 风险（用户已知）
- 首次配网期间热点开放、使用 http：附近的人能连上；管理员密码和家里 Wi-Fi 密码在这几分钟内明文传输。之后的管理全部走 https。
- 用户名密码可能被暴力猜测：靠冷却和长度要求缓解。
- 实机验证首次配网，需要让设备回到“没有管理员”的状态（恢复出厂或另一台设备），执行前单独确认。

## 第 1 段实现记录（2026-10-28）

设计在实现时做了调整：发现 `crypto.subtle` 在 http 页面上不可用，改成**密码只在浏览器里使用、绝不发给设备**。
- `crates/edge/src/web/password.js`：用户名（NFC、去首尾空格、转小写，1–32 个字符）加密码（8–64 个字符），以 `RustSimHub.Password.v1` + 设备公钥 + 用户名为盐，做 PBKDF2-HMAC-SHA256（210000 次），得到 Ed25519 种子。SHA-256、SHA-512、Ed25519 都是纯 JS 实现，http 页面也能用；https 页面可以把种子导入 WebCrypto，私钥设为不可导出。设备只保存公钥。任何浏览器输入同样的用户名和密码，都会得到同一个管理员身份，所以不再需要配对。
- 认证层：`LocalSetup::begin_open/finish_open`，即不需要设置码的一次性认领。仍然要签名挑战，仍然只认最后一次发出的挑战，计入尝试次数和有效期，设备已有管理员时一律拒绝。
- 线协议：新增 `setup_open_challenge` / `setup_open_finish`，不带设置码，也不带令牌；完成请求的编号和签名格式严格校验。
- Core：只有首次配网热点处于 Ready 时才处理这两个命令（`first_setup_ready()`），否则拒绝，且不创建任何东西。
- 测试：auth 43（新增 2：一次性、签名、只认最后的挑战、坏签名、已有管理员、次数和有效期），wire 19（新增 1），Core 59（新增 1：没有就绪热点时拒绝，不创建管理员，窗口仍可用），网页密码测试 5 组（FIPS/RFC 8032/PBKDF2 向量，与 Node WebCrypto 一致，边界输入），其余网页测试全部通过；fmt 和 clippy 干净。
- **尚未覆盖**：热点就绪时允许认领的分支，需要运行中的配网引导，留到第 2、3 段的集成测试；`password.js` 还没接进页面，也没加入 edge 的静态资源列表。

## 第 2 段实现记录（开放热点部分，2026-10-28）

- Core 发给 Root 的启动提示新增 `open` 字段：首次配网窗口（引导窗口）为 true；管理员窗口为 false，且 false 时不写入，线上格式与原来完全一致。旧版 Root 收到 `open` 会因未知字段拒绝启动，版本不匹配时安全失败。安装契约不变。
- Root：`Credentials::open_variant(设备名)` 生成开放热点凭据，热点名 `RustSimHub-<设备名后 4 位>`，沿用同一配置 UUID，回滚仍只认这一个配置。热点配置不带 `802-11-wireless-security`；读回校验区分开放与加密，同一 UUID 下类型不符一律判为不匹配。`/etc/rustsimhub/device-name` 缺失或格式不对时不启动任何热点（安全失败，失败后也会等待，不会空转）。
- 测试：setup-ap 95（新增 3：开放凭据的命名和非法名称、开放与加密配置互不匹配、提示字段的线上格式），Core 50（引导窗口的提示 `open=true`，管理员窗口 `open=false`），fmt 和 clippy 干净。
- **尚未完成**：扫描附近 Wi-Fi；开放热点在 wcn36xx 上的实机表现；保护表（nft）对开放热点的放行规则不变，等第 3 段加 80 端口时一并调整。

## 第 2 段实现记录（扫描部分）

- Core 在首次配网热点启动前（设备空闲检查之后、发出启动提示之前），用 3 秒上限只读一次 NM 的 Wi-Fi 缓存，不请求扫描、不改连接；只保存非空的结果。
- 首次配网热点就绪期间，如果当前缓存为空，“附近的 Wi-Fi”接口改为返回这份快照，`source` 标为 `before_setup_ap`，所有条目标为未连接；快照超过 10 分钟不再使用。其他情况仍返回当前缓存。接口仍然要求管理员身份，并经过最近一次签名确认。
- 测试：Core 网络和热点相关 72 通过（新增 1），clippy 干净。
- **限制和待实机确认**：热点开启时能否重新扫描未知，页面上的“重新扫描”暂不提供，可以手动输入名称；NM 在没有连接时会自行定期扫描，首次配网前缓存一般不空，但需要实机确认。

## 第 3 段实现记录（自动弹出与 http 配网页，2026-10-28）

- 配网 edge 新增 `captive_listen`（固定为 `192.168.100.1:8080`，其他值拒绝启动），独立的纯 http 服务：`/` 配网页、`/setup.js`、`/password.js`、`/style.css`；`/api/v2` 只放行首次配网需要的命令（设备身份、无设置码认领、登录与续期、附近 Wi-Fi、热点配网的状态/试连/保存/取消），其他命令返回 404，Core 仍逐条鉴权。API 要求 Host 为 `192.168.100.1`、Origin 为 `http://192.168.100.1`、JSON 和请求标记；请求体上限 16 KB。其他任何路径或域名（系统联网探测）一律 302 跳转到 `http://192.168.100.1/`，让手机自动弹出页面。安全响应头与 https 页面一致。
- Root 对配网 edge 配置的镜像校验接受 `captive_listen`，但只接受固定地址和端口。
- 热点防火墙：只有开放的首次配网热点才额外放行 DNS（udp/tcp 53）和 8080，都只限热点网段访问本机；另加 nat 链把 80 端口重定向到 8080，edge 仍然无特权。新规则插在最后的 drop 之前。参考 JSON 用设备上的 nft 1.1.3 在临时网络命名空间里生成；原有两份参考仍一致（9/10 行），开放变体为 14/15 行。加密热点的规则完全不变。
- 固件新增 `/etc/NetworkManager/dnsmasq-shared.d/rustsimhub-setup.conf`：所有域名都解析到热点地址。
- 测试：edge 36（新增 2：只放行白名单命令；探测地址跳转、页面头、Origin 必须精确、超大请求拒绝），setup-ap 97（新增 2：只接受固定的 captive 监听；只有开放热点打开 DNS 和配网页，规则顺序与参考行数），Core 50，fmt 和 clippy 干净。
- **尚未完成**：`setup.html`/`setup.js` 目前只是占位，第 4 段实现；dnsmasq 配置还没登记到系统镜像组装清单；以上都需要实机验证（手机能否自动弹页、NM 是否读取 dnsmasq-shared.d）。
