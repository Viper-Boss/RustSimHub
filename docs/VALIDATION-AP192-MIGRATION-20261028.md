## 过程

1. **重启**（用户批准）：UPD-04 用掉了本次开机的自动恢复机会，安装预检按规则拒绝。重启后新的 boot_id，所有服务正常，恢复机会恢复，内核日志无 oops。
2. **构建**：WSL 全新目录交叉编译 11 个 ARM 程序，音频 QEMU 33 项通过。前两次失败，原因都是构建脚本从主仓库目录导入打包工具，那里还是旧契约，所以契约对不上；随后又因工具的输出目录检查失败。改为从冻结源码导入工具，并把输出位置指向本仓库的私有目录后通过。失败的半成品已保留。

4. **admit-stage 正确拒绝了单独安装应用 57**：退出码 3，`maintenance_required`，候选原因是 `root_mode_unavailable`。已安装的 Root 契约还是旧地址，新 Core 的契约是新地址，两者对不上。启动器的规则是：已安装契约、启动器编译的契约、Core 的契约三者一致，才以配网模式启动，否则自动降级为转发模式，电话、短信不受影响。所以改契约必须作为一次维护，和应用组一起切换。
5. **迁移窗口**（一次停机窗口，带 10 分钟保护定时器）：备份并原子替换契约、热点助手、Core 启动器；把旧的热点配置服务安装目录和热点材料改名挪到备份目录；用 `install.sh` 里相同的固定命令重新生成：edge 用签名应用 57 包里的程序，以 edge 用户在受限沙箱中运行，热点助手执行 `--prepare-from-core`；核对新地址、证书名和权限；用现有更新器的 `stage` 暂存应用 57；启动应用组，开机选择单元试运行 57。随后核对试运行状态，做健康确认，最后单独替换更新器。
6. **迁移窗口内的失败（都已保留记录）**：
   - 第一次：空闲检查比 `install.sh` 更严格，把热点助手建立的 0 字节 `.lock` 当成了“有记录”，在预检阶段就停了，没有任何改动。
