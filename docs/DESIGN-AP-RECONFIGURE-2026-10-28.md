# 设计草案：已联网设备的重新配网、“开启热点”按钮与拒绝原因显示（2026-10-28）

状态：用户 2026-10-28 确认设计。第一段（拒绝原因，PR #48）、第二段（固定网址，PR #49）、第三段（重新配网与“开启热点”按钮）代码已完成，并通过隔离测试，**均未部署**。

## 现状（读代码确认）

- 热点事务（`crates/setup-ap/src/transaction.rs`、`nm.rs`）的每一步都假设 wlan0 是断开的，并且设备上**没有保存过任何 Wi-Fi**：预检、建立检查点、激活热点、回滚后的核对，都要求 wlan0 处于“断开”状态；试连（`nm/station.rs` 的 `begin`）也拒绝任何其他 Wi-Fi 配置。所以现在的热点只能用于首次配置。
- Root 拒绝时，只回传“已关闭”，不带原因。Core 和网页只能显示“操作结果未确认”。
- **身份连续性没有解决（AP-08）**：浏览器的所有者密钥按网址（origin）保存。日常地址 `192.168.120.167`、热点地址 `192.168.100.1`、换网后的新 IP，在浏览器看来是三个不同的网站，身份互不相通。

## 核心问题

已联网的设备一开热点，wlan0 就离开原网络，用户的页面会断开。用户需要在热点地址上继续“试连 / 确认保存”，但到了那里浏览器已经不认他是所有者。只做 Root 和 Core 的重新配网逻辑，网页上依然走不通。

## 建议方案：固定网址 + 三段开发

### 第一段：固定配置网址（解决 AP-08 的身份连续性）

- 给设备一个**固定主机名**，例如 `rustsimhub-0087.local`（序列号后 4 位，和热点名称一致）。
- 在家里网络中，用 mDNS 广播这个名字，指向设备当前的 IP；在热点中，用热点自带的 DNS 把同一个名字解析到 `192.168.100.1`。
- 日常页面和热点页面都用 `https://rustsimhub-0087.local:8443`，浏览器视为同一个网站，**所有者身份自然连续**。
- TLS 证书改为签发给这个主机名（另加 IP 作为备用名称）。
- 风险和前提：手机或电脑需要支持 `.local` 解析（iOS、macOS、Windows 10 及以上、多数 Android 浏览器都支持）。旧的 IP 网址保留，作为后备。

### 第二段：Root 重新配网模式（设备已保存一个 Wi-Fi）

- **预检**：允许“恰好保存了一个 Wi-Fi 配置 S，且 wlan0 连着 S 或处于断开状态”。记录 S 的路径、UUID 和配置摘要，其余条件（没有自动连接的 gsm 配置、没有现存检查点、网段不冲突、支持 AP）不变。
- **检查点**：在 S 连接状态下建立 NetworkManager 检查点；回滚时由 NM 恢复 S 的连接。
- **激活热点**：直接在 wlan0 上激活热点配置，NM 会自动断开 S。S 的配置本身**不修改**。
- **试连**：允许 S 作为唯一的“已记录配置”存在，每一步都核对 S 没被改动。
- **保存**：新网络以优先级 50、自动连接的方式保存，S 保留作为后备。删除旧网络作为单独的后续选项。
- **回滚核对**：确认热点配置已删除、检查点已回滚；wlan0 重新连上 S，或者处于断开但 S 仍可自动连接的状态，即算恢复。如果在限定时间内无法确认，就记为 Unknown，保留网络保护，不猜测成功。
- **首次配置路径不变。**

### 第三段：拒绝原因与“开启热点”按钮

- Root 预检失败时，回执中带一个有限的原因码，例如：`station_saved`（首次配置模式下已有保存的 Wi-Fi）、`wifi_disabled`、`checkpoint_exists`、`subnet_conflict`、`ap_unsupported`、`gsm_autoconnect`、`busy`。新增字段可选，旧版本忽略它。
- Core 把原因码透传给网页；网页显示中文原因，例如“设备已连接 Wi-Fi，请使用‘重新配网’”。
- 网页把“开启热点”做成单独的按钮：先开热点并显示热点名称和固定网址，再在热点页面里试连、保存。Wi-Fi 扫描选择与手动输入放在同一个页面（另一项需求，可以同步做）。

## 失败恢复底线

- 任何一步失败，都回到原来的 Wi-Fi（S）。检查点到期后，NM 会自动回滚。
- 结果不明时，记为 Unknown 并保留保护，不自动重试；可以经 USB 维护链路人工核对。
- 实测时提前打开 USB 维护链路，热点开启期间也能观察设备。

## 需要用户决定

1. 是否采用“固定主机名 `.local`”方案来解决身份连续性（推荐）。不采用的话，重新配网只能在已经和设备身份配对过的同一网址上完成，而热点地址的网址与日常地址不同，实际上走不通。
2. 三段的顺序：建议按 第三段（原因显示，小而独立）→ 第一段 → 第二段 的顺序做，每段单独测试、单独部署。

## 第三段实现记录（2026-10-28）

- 预检：最多一个已保存的 802-11-wireless 配置，记下它的路径作为“原 Wi-Fi”；wlan0 必须空闲，或正在连接/已连接这个原 Wi-Fi。保存了多个 Wi-Fi → `station_saved`；被其他连接占用 → `station_connected`。原 Wi-Fi 从不修改、从不删除（模拟测试中对它调用 Delete 会直接 panic）。
- 建检查点、激活热点、回滚后的状态核对，都改为“空闲，或原 Wi-Fi 正在连接/已连接”。回滚由 NM 检查点恢复原 Wi-Fi 的连接状态。
- 试连阶段允许原 Wi-Fi 作为已知配置存在。
- 网页：新增“开启热点”按钮，和“开始试连”共用同一套持久记录与“最多开启一次”的逻辑；开启后提示用户连接热点，打开同一个固定网址继续。
- 测试：setup-ap 91（新增 3：替换后回滚恢复原 Wi-Fi，原 Wi-Fi 连接/未连接两种情况都覆盖；多个 Wi-Fi 或被其他连接占用时拒绝且不做任何改动；预检之后出现其他连接时，阻止建检查点和激活），网页 16/16（新增 2 组）。
- **尚未验证**：保存新网络（commit）路径在“已有原 Wi-Fi”时的行为，只有首次配置模式下的模拟测试；保存后原 Wi-Fi 作为后备保留；真实 NetworkManager 检查点恢复原 Wi-Fi 的实际表现，需要实机验证。

## 部署前补充：日常网页跟随 Wi-Fi 地址（2026-10-28）

- 问题：日常 edge 监听固定的 192.168.120.167:8443。重新配网换到别的网络后，地址变化，页面就打不开了（edge 本身不会崩溃，只是一直重试绑定旧地址）。
- 修复：当 edge 的主网址是 `https://<设备名>.local:8443` 时，除了配置里固定的地址，还监听 wlan0 当前的私有地址（读 `/proc/net/fib_trie` 和 `/proc/net/route`，只取 wlan0 直连网段内的本机地址，最多 2 个），随原有的 5 秒重试循环自动跟进。非 `.local` 配置的行为不变。浏览器只用 `.local` 网址访问，Host 必须匹配某个已配置的网址，所以新地址只是“新的入口”，不会放宽来源检查。
- 日常 edge（media 配置）准备与核对命令支持 `NAME,ALIAS` 形式，别名作为附加网址（主名 `.local`，别名为原 IP），证书同时包含两个名字。
- 测试：edge 34 通过（新增 2：只列 wlan0 网段内的本机私有地址；新网段被识别、公网地址被忽略），fmt/clippy 干净。
- **尚未验证**：媒体工作进程（native/audio-alsa）的允许绑定地址仍是固定的，换网络后通话媒体需要另行处理；实机换网后的实际表现。
