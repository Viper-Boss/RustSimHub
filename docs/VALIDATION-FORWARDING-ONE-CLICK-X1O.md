## 使用方式

保存一个 Bark 目标后，在首页点 **一键测试 Bark**。网页自动完成所有者登录、目标核对、保存本机请求编号、提交一次测试、观察回执和显示设备收尾结果。不需要展开转发配置或手动开启服务。初版用于转发已确认关闭的状态；已有日常转发开启时拒绝临时测试，避免改变用户的正常运行状态。多个 Bark 目标不擅自选择。

## 设备端实现

- 新增有限鉴权命令 `forwarding_quick_test`，仅允许最近登录的所有者、匹配当前配置代次和已保存目标；沿用现有请求大小、规范 UUID 和未知字段拒绝规则。
- Core 接管一次测试的生命周期，HTTP 连接和浏览器页面不是其保活来源。它通过既有固定 Root 协调服务启动低权限 worker，仍使用原有 DNS/TLS、出口绑定和逐阶段 Owner/SIM/请求摘要复核。
- Queue 内建立不可续期的 45 秒进程内测试窗口。测试不修改保存的开关、规则、凭据或配置代次；窗口内跳过真实短信捕获及业务游标推进，只允许本次精确请求编号和目标的合成通知。其他配置/普通发送请求在收尾前拒绝。
- 合成任务从受理时即持久化为已保留的进行中状态，真正领取时才生成 attempt ID。新 Core 重启或回退到原兼容 Core 后，既有恢复逻辑将其保留为 Unknown，不会成为以后开启日常转发时被补发的排队任务。
- 完成、启动失败、丢失回复或有界等待结束后，先撤销测试权限，取消未领取任务或保留已领取任务的不确定性，再执行一次固定 Root 协调收尾。撤销先于回执写入，回执写失败也不能继续获取发送权限。浏览器退出不取消收尾；无法核实整组关闭时不会展示关闭成功。
- 测试过程中，Root/worker 使用有效的临时运行状态；所有者界面同时标明“合成测试进行中；真实短信转发保持关闭”。日常配置控件暂时禁用。

## 网页与防重

首页增加一个入口，结果仍显示在原测试提示区，可复制测试结果。请求受理前先使用共享 IndexedDB 槽保存最小元数据；双击不重复受理，其他页已有操作时不覆盖。丢失受理回复后，下一次点击只查询原编号，不重新发送。Unknown、登录失效、存储失败及观察超时均保留待核对记录。成功/失败/取消的精确终态和关闭证明核对后才归档。
