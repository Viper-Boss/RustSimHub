## 已实现

- 首页直接显示短信列表、完整正文和写短信入口；列表展示发件人、时间和有界预览，不再要求用户先阅读记录ID或JSON。
- 登录后填写号码/正文，确认一次后完成原有准备、持久防重标记、提交和结果查询流程。后台权限、SIM代次及操作幂等机制不变。
- 提交前必须保存客户端标记。重复点击、存储失败、注销、草稿变化及超时不触发自动重发；结果不确定时保留操作，只允许查询。
- 发送结果确认后可显式完成、清空草稿，并保存最近64笔不含号码/正文的客户端回执。放弃从未提交的准备操作只关闭本地入口，不冒充核心已取消；核心不会自行发送准备操作。
- 回收站列表和详情可直接阅读。候选旧短信比较继续使用已有两栏核对，保留各自不同ID，不自动合并。
- 列表预览不会批量标记已读；显式打开一条短信才沿用已有通知已读接口。
- 配对、网络配置及手动调试折叠。日常浏览不再持续占用白色配置灯；打开配置面板仍使用既有配置指示流程。

## 接口及资源边界

存储收件箱/回收站摘要增加可选display字段，内容仅为sender、timestamp、preview，分别最多64、48、96个Unicode字符；最多32条仍满足64KiB IPC边界。没有新增数据库迁移、裸硬件命令、权限或短信发送接口。详情和原始正文完整保留，调试格式化摘要继续隐去内容。

前端仅以textContent显示短信。UTF-8正文最多4096字节，拒绝空正文、NUL和非法号码；准备回执校验UUID格式，查询回执必须匹配当前操作ID及已知状态。客户端标记先落盘，再请求提交。

“已提交发送”只表示核心提交结果，不承诺接收方收到。Unknown仍需原操作核验，不能清除后自动重发。
