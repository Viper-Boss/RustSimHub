## 第一批PR：计量和月结（B-01～B-04）

### B-01 / 对应NET-01：先锁定现有语义

1. 逐个阅读 `Policy::valid`、`State::new/valid/sample`、月结窗口、限额判断和持久状态读写，画出实际数据流。
2. 列出已有测试覆盖和确切缺口，不把功能已存在写成自己新增。
3. 冻结时区、reset_day、边界时间、rx/tx单位及统计来源；字段不明确先在PR提问。
4. 使用真实函数构造小型合成样例，记录输入/结果/期望，第一份提交应可复现。

### B-02 / 对应NET-01：日历和时钟矩阵

1. 月结日1/28/29/30/31，跨小月/闰年/跨年和结算瞬间各侧一秒。
2. 同日回拨、跨日回拨、远期跳变、无效时间和重启后时钟未就绪。
3. 需要保护时使用已有uncertain状态，不靠清空账本或免费重置额度兜底。
4. 保留原有SIM隔离和账期规则；改变语义必须有具体反例、兼容说明及主线审核。

### B-03 / 对应NET-02：计数器与接口变化

1. 单调累计、rx/tx分开、恰好限额、单字节越界及u64溢出。
2. boot ID变化、同boot计数器清零/变小、接口删除重建、计量源缺失/不可读和畸形输入。
3. SIM切换前后分账；旧身份/旧计量源的迟到输入不能冲掉新状态。
4. 不允许负差值、重复扣费或错误赠送新额度；错误状态不得显示“还有全部额度”。
5. 用真实State执行多步序列和重开，不仅用一个静态JSON比较。

### B-04 / 对应NET-01/02：持久化与失败恢复

1. 在临时目录验证正常保存/重开、截断、错误版本、超大文件、原子替换失败及权限/链接拒绝。
2. 写入失败保持原有效账本并明确报错；不要覆盖损坏现场或悄悄用State::new放行。
3. 验证禁用流量限制与关闭蜂窝数据是两个概念，不能为了测试额度而触发连接。
4. 提交第一批PR：最小代码修正+测试；说明未运行真实nft/NetworkManager和未验真实卡计费。

## 第二批PR：显示与交接（B-05～B-08）

### B-05 / 对应NET-03：无线和链路字段

1. 合成检查IPv4/IPv6、DNS、APN、网络制式、频段/信道/上下行频率、带宽、小区ID/TAC、RSRP/RSRQ/SINR。
2. 缺失、null、非法数值、未知枚举、陈旧快照和断线分别显示准确状态，不显示NaN/undefined或编造0。

4. 所有设备文本按文本渲染；供应商字符串/异常信息不能进入可执行HTML。

### B-06 / 对应NET-03：速率和月用量

1. 明确B/s与bit/s、MB与MiB、总量与收/发量，避免重复乘8或1000/1024混淆。
2. 间隔0、倒退、长暂停、计数器重建和样本缺失不能产生负速率/无限大。
3. 页面隐藏/退出后不启动额外轮询；重新登录与迟到响应沿用现有会话边界。
4. 状态刷新不跑测速、不访问公网，不把只读状态当成有可用互联网。
