## 第一批：事件同步和对象生命周期（D-01～D-04）

### D-01 / SMS-02：先梳理现有状态和不变量

1. 阅读storage收件/删除恢复及Core observer的实际入口和既有测试，画出source路径、记录ID、line epoch、事件游标关系。
2. 给每个拟修问题建立最小输入序列和期望结果，先证明缺陷或说明是已有行为补验。
3. 固定原则：收到相同事件不重复副作用，失败不推进成功游标，旧代次不能污染新SIM。
4. 不把短信正文/号码相同当作物理同一短信；不能为方便测试关闭身份/线路隔离。

### D-02 / SMS-02：旧游标、分页和乱序

1. 覆盖过旧游标、分页边界、重复/乱序/丢事件、列表读取失败和恢复连接。
2. 读取/消费/持久化失败后不丢项、不提前推进游标；重读保持原稳定ID。
3. 删除/恢复/已读事件追赶不能使旧记录复活或把新记录误删。
4. 使用真实Store/observer模块多步执行，保存数据库再重开验证；不能只比较手写期望JSON。

### D-03 / SMS-04：ModemManager对象换代

1. 覆盖同一路径复用、对象销毁重建、重连、信号丢失、大于旧批次上限的列表以及轮询/信号竞争。
2. 切换SIM/line后，旧异步读取完成不得写入新代次；后端不可用不等于删除本地已确认短信。
3. SIM满、读失败和部分列表不能伪装成完整空收件箱；保留恢复后的可查询证据。
4. 用已有本地模拟源注入错误，不运行真实ModemManager/nmcli或连接系统D-Bus。

### D-04 / 第一批交付

1. 运行storage与Core的针对性测试、fmt、相应严格Clippy；能运行workspace回归再记录，不把未运行写通过。
2. 报告每个输入序列、真实状态/事件数量、修复前后差异和原数据保持结果。
3. 交付小PR和完整40位HEAD，区分“发现并修正缺陷”与“既有行为已复核”。不改SMS台账为done。

## 第二批：内容、重复候选和提交恢复（D-05～D-08）

### D-05 / SMS-03：内容与边界

1. 中文、emoji、组合字符、长文本、分段不完整、空正文、二进制、极限长度和超限。
2. 检查字节/字符限制和截断标记；无效或未完整内容不冒充完整正文，不崩溃。
3. 如果现有后端已由ModemManager解码，不另造PDU解码器；列出尚未暴露的原始PDU边界作为主线缺口。
4. 夹具正文可公开、明确合成；错误消息/报告不得输出真实通信数据。

### D-06 / SMS-05：疑似重复和跨启动

1. 同号码/正文/时间但不同稳定ID仍保留；缺乏可证明来源时标候选，不自动合并。
2. 对象重观察与恢复后再次观察不反复增加相同副作用；旧候选与当前记录可分别查询。
3. 删除/恢复保持当前ID，旧记录只读，不改变候选对方；重开后标记与权限一致。
4. 本批不改网页；有交互缺口写具体需求给主线，避免和其他人的前端工作冲突。

### D-07 / SMS-06：持久操作故障矩阵

1. 在现有prepare/提交/确认各边界注入保存失败、退出、数据库事务失败、超时/回复丢失。
2. 验证一个操作最多一个实际发送尝试；Unknown只查询原ID，不自动新建幂等键或重发。
3. 重启/恢复不能让旧prepared重新成为发送任务，也不能丢弃已有发送回执。
4. 模拟发送器统计调用次数，不调用真实MM发送；若发现生产修改涉及跨模块接口，先交复现和最小提案，不扩大修改范围。

### D-08 / 第二批交付

1. `cargo test -p rustsimhub-storage --locked`，Core中实际受影响测试、fmt和对应Clippy；记录完整命令/退出码。
2. 将矩阵按“新增测试/修复/已有行为/未实现/未运行”分类，给出逐HEAD报告。
3. 写实机补验清单：新发送授权、双端同步、真实对象/信号、换卡和冷启动；不要求自己获取设备。
4. 全局进度、签名构建和设备部署由主线审核后处理，不以离线测试宣称运营商短信、真实SIM存储满或冷启动通过。
