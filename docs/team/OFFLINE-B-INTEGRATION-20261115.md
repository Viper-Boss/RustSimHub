## 4. 执行步骤

### B0：真实基线、已有成果和差距表

1. 记录main和个人HEAD、环境/工具链、干净状态、可用隔离能力与现有PR。不要把草稿和未提交本机代码纳入候选。
2. 核对`tools/product-integration/inputs.json`、当前交付报告与实际Git祖先；旧清单覆盖不了新PR时按证据更新，不能只按PR标题或“已合并”判完整。
3. 对第5节29项和第6节A的验证覆盖，记录`已实现可复验 / 新缺口 / 仅设备 / 缺输入`，优先补实际缺陷和没有的测试，不重写已交代码。
4. 建立源码、模拟/PID1、ARM构建、QEMU、设备、公网五类证据，不相互替代；每个未运行项写原因。
5. 不把旧rootfs/旧应用号、历史签名包或旧系统健康当成最新组合。缺真实输入时先做可复现负对照和拒绝路径。
6. 将盘点写入`docs/deliveries/OFFLINE-B-INVENTORY-20261115.md`，继续执行后续实现，不只停在盘点。

### B1：同源产品构建与未签名候选

1. 核现有`tools/product-release/release.py`的真实profiles和参数，复用它，不重新写一个跳验证打包器。
2. 构建输入绑定完整提交、Git tree/归档SHA、Cargo/Go锁、静态资源/WASM、SDK逐文件/patch/许可证和真实程序元数据。源码构建过程中变动或混源直接拒绝。
3. A没交完时用当前main独立跑；消费A成果时逐一核其精确实现/PR HEAD，不能把报告JSON或uploaded binary当可信来源。代码追加后旧证据需复审。
4. 实际验证legacy、product、email、recovery等仓库已支持profile的组合和拒绝矩阵；不要擅自发明已可用的profile。新载荷只在有格式/版本兼容证据时接。
5. 核Core/Edge/NKN SDK/Root/音频等程序的实际版本/功能/链接情况，但不修改音频/蓝牙源码。无法构建某项要单列缺口，不替换成空壳或`--version`假输出。
6. 对归档穿越/链接/重复项、缺文件/混源/错架构、伪造模式/私钥/未知schema等做实际失败测试，不只测自家manifest互相比较。
7. 仅生成`unsigned`候选，明确`signed=false`、未分配设备epoch、`installable=false`、`hardware_tested=false`。已有离线合成签名夹具可在临时目录使用，不能叫生产签名。
8. 缺sysroot、固定SDK源码或许可证材料时清楚写缺哪一项；继续打包器/反例工作，不能下载未知固件或拿私人设备备份顶替。

现有命令形状可参考：

```sh
python3 tools/product-integration/verify.py --repository . --integration 完整40位SHA --require-complete
python3 tools/product-release/release.py --help
python3 -m unittest discover -s tools/product-release -p 'test_*.py'
```

`release.py`实际需要`--profile/--archive/--repository/--output/--roles/--sysroot/--audio-sysroot/--revision/--source`，某些profile另需`--verified-sdk-stage`。本书不提供不存在的万能参数；先读源码与help，填自己的真实构建输入。未满足前置不运行安装或“跳过验证”。

### B2：Root材料、健康确认和安装故障

1. 复验固定Root目标、原角色表、组/UID/目录归属、可写/只读范围和当前程序模式，不擅自加Root写入目标或重用蓝牙/音频UID。
2. 对相同候选和完整组执行有界准入、唯一启动、原进程/原上下文健康确认；不是Root自称ready就能确认。
3. 覆盖超时/断连/晚回复、错误Core/UID/PID、旧版本/旧进程、锁被占用、子进程未退出和清理未知；不延长授权来通过。
4. 正常单元与隔离PID1、资源/能力/cgroup/nft范围做可运行本机测试；支持不足明确fail-closed，不能改为默认允许。
5. 不能为了package通过把AP/SMTP或新统计模式冒称已获得原健康接口支持；支持矩阵与拒绝路径要真实。
6. 输出给主线的安装/回退步骤和准确输入摘要；不签名、不上传设备、不启用/停止服务，不实际申请维护窗口。

### B3：迁移、备份与恢复的可执行故障矩阵

1. 复用现有应用/Root/profile/数据库版本契约，列出明确支持的前后版本，不以“回滚二进制”推定数据库可回滚。
2. 使用生成的测试数据库，保留提交后写入、短信删除/恢复/疑似重复、outbox/Unknown、统计Pending与独立参与授权；不能把用户新数据恢复到旧快照抹掉。
3. 对SIGKILL、失败注入、只读、写满、截断、部分发布/目录同步失败和重启做实际本机执行，不只assert代码里存在分支。
4. 同一原幂等ID恢复后只查询原操作，不自动拨号/发短信/递送/发链上交易。数据存在但确认不明要保留原状态。
5. 对错身份、错realm、错schema/epoch、坏备份、链接/路径替换、锁冲突和不完整恢复明确拒绝；不自动生成新Owner或统计密钥掩盖问题。
6. 原签名/信任/反回滚约束保留；测试钥匙与生产密钥分开，不能扩大正式接受范围。
7. 在隔离镜像/目录中运行可执行恢复/校验工具，记录真正字节核对和原记录保持；不访问原盘、boot/GPT/NV/校准区或ADB/EDL。
8. 给负责人列真实断电/完整恢复尚需什么环境与物理步骤；合成PID1和kill不等于真实板级断电验收。

### B4：跨模块离线验证与独立一键入口

1. 在`tools/offline-b/`新增有界统一运行器，串联实际已有验证器；缺依赖输出`not_run`及原因，不能整套强制绿色。
2. 为短信、电话控制、转发、AP/NetworkManager、NAS、状态灯模型和NKN/统计准备本机对端/事件序列。生产实现有缺陷交A，不改成只返回成功的假端点。
3. 复验原ID、跨客户端最新状态、撤权、重启、乱序/断开/时钟变化；模拟接通/计数不可当真通话/真实安装数。
4. 对实际主页/ESM/CSP/IndexedDB跑三宽度、权限失败、缺模块和迟到结果负对照；不使用用户原Chrome钥匙或更改Windows受信任根。
5. 同源WASM/网页/静态资源和模式路由必须能核验；截图与真实API/权限证据分开。
6. 电话/PCM使用有限合成帧和标准测试信号，不录真实声音、不改变native或AirSIM；没有声卡不声称听音通过。
7. NKN统计只在回环假节点/实际本地编码上测，公网提交测试留主线；HTTP接受或本地JSON通过不算链上确认。
8. 将新检查接到CI和主线运行器时保持真实退出码；CI计费零步骤明确未运行，不重复刷CI或删除门禁。

### B5：安全、依赖、资源和发行材料

1. 产出可核对的接口/进程/UID/能力/网络出口/信任边界清单；区分已启用、候选关闭和仅设计。
2. 补Auth/跨线路/重放、输入有界/模糊语料、Root路径拒绝和公开包秘密扫描；只扫描合成或准备发布的内容，不把生产秘密写到日志。
3. 根据实际链接模块、锁文件和程序构建信息核许可证/来源，不拿仓库未编译依赖冒充实际闭包；漏洞与缓解/未修风险逐项保留。
4. 压力测试限定进程/内存/文件/网络/时间预算，异常时回收自己创建的测试资源。只测本机构造负载，不修改主机系统服务、网络或他人目录。
5. CPU/RSS/延迟基准写环境、采样方法和可复现命令；没有板子不能报告棒子功耗、温度、真实速率或72小时长稳通过。
6. 输出用户/维护/升级/恢复文档、支持矩阵、未签名包说明和逐项验收清单；第二台和真实恢复只列待测前置，不能填已通过。

### B6：交付规则

1. 一个可评审子包一个PR，别把数十个跨模块改动塞一笔；只推自己的同仓库分支，不自合并、强推main或处理草稿。
2. 报告写起始/当前完整HEAD、真实修改路径、构建输入/制品摘要、实际命令/退出码/日志摘要、失败/忽略/未运行和资源回收情况。
3. 对每个动作区分：已有代码复验、新修复、模拟、本机PID1、ARM构建/QEMU、设备/公网未验收。缺材料不能用旧制品改标签充数。
4. 给A的接口缺陷和给主线的签名/设备前置分别列；依赖未就绪时继续其余独立子包。
5. 保留参考来源/许可证、原始失败和后续成功，不改作者或伪造工时；敏感材料只放自己的忽略目录。
6. 报告不修改全局看板或宣布100%。本包完成是离线交付，发布/安装/真实验收由负责人决定和执行。
