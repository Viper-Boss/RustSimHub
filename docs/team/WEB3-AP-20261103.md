# 窗口1 · WEB3-AP：热点配网产品收尾

先读同目录 `WEB-PRODUCT-DELEGATION-20261103.md`，其中起点、固定PR、权限、公共接口和文件归属均适用。目标是交可执行的产品改动，不是重写设计报告。建议分支 `codex/web3-ap-completion-20261103`。

## 已知事实与范围

当前main已有Core重扫模块、Scan命令、Root通道和 `setup.js` 的扫描组件绑定。旧PR69正文不是当前状态。首次页面仍区分读取缓存/重扫，`networks()`文本仍宣称热点期间只读列表；需核实用户实际看到的入口、能力和端到端状态后补缺口，不先断言后台没有扫描。

可写：`crates/core/src/setup_ap_control.rs`及其子树、`crates/edge/src/web/setup.js`、`ap-wifi.js`及原扫描组件、首配HTML和首配专用样式、对应独立测试。Root扫描实现只在已复现缺陷处最小修改，保持现有协议与有限路径。不要动全局 `app.js`、六个旧VM脚本、Auth/wire公共文件、恢复网络actor或更新器。

## 十个开发动作

1. **画出实际调用链并跑基线。** 从首配按钮到原Core/Root/NM，记录功能开关、近期Owner/父事务、能力投影、回执与UI更新。复现实际缺口；已有部分逐项注明复用，不重写一套事务。
2. **做单一清楚的刷新入口。** 用户明确点击“刷新附近Wi‑Fi”时，在支持的热点配置事务中调用原有有界重扫；普通页面读取不偷偷扫描。不能把仅更新读取时间写成扫描完成。确实不支持时说明原因并允许手输SSID，不能静默返回旧列表当新结果。
3. **完整前后端接线。** 需要的近期Owner/代次/权限、父窗口、全局网络协调及既有Begin/Status/Cancel均接真实生产路径；保留操作ID。IPC丢回复只查询原ID，不再次Begin。
4. **兑现Root事实。** Ready/Failed/Refused/Unknown、冷却剩余、次数、父截止和恢复情况按实际权威回执展示；空扫描替换成真实空列表，查询旧轮不能覆盖新快照。不得扩大既有30秒/8次/父租约预算。
5. **简化试连→保存。** 同一页面保留明确阶段；断线恢复后能查询原试连和保存。密码不持久化，重开后缺密码要在需要时明确重输；不能用“已保存”描述只保留了本地进度。
6. **统一互斥。** 扫描、试连、保存、取消不并发新副作用；在冷却/冲突中不排队以后自动执行。按钮禁用旁显示具体原因，退出或换设备后旧异步响应不恢复按钮或回填状态。
7. **补失败矩阵。** 正确/错误密码、开关不支持、能力陈旧、扫描空结果、丢Begin回执、掉线后查询、取消/撤权、两标签页、服务退出及恢复失败。必须走实际控制器，不用一个复制算法的假状态机。
8. **真实浏览器回归。** 复用仓库首配浏览器环境，在loopback合成后端上用真实模块/HTML，检查320/390/桌面宽度、关闭/重开、只有一个日常刷新入口及明确错误文案。无浏览器能力准确记缺项，但继续其余开发。
9. **运行针对性验证。** Core/Edge/setup-ap相关 `cargo test --locked`，对应严格Clippy、仅修改文件fmt及首配Node/浏览器检查；记录实际数和Root/RF未运行项。不改workflow，不给其他文件格式化。
10. **分阶段交产品PR。** 建议先控制/回执缺陷，再网页流程。报告 `docs/deliveries/web3-ap-completion-20261103.md`，含修复前实际失败、修改后结果、完整SHA、重用关系和手机最终验收步骤。不得自行部署或合并草稿69。

## 完成标准

真实生产代码可从用户点击进入原有事务、按同一ID恢复并正确完成/拒绝；缺能力不会伪装成功。用户不需要面对若干相似“刷新/查询/准备/提交”按钮猜下一步。默认授权和Root限制保持，已有试连保存回归不退化。

若开工最新main已解决某项，给出精确代码位置和真实验证，继续其余缺口，不强行制造改动。物理热点/手机射频和签名部署由负责人最后验收。
