这是负责人主线的辅助工作包，适合在网页版 Codex 的 Linux 环境执行。执行者沿用自己实际登录的 GitHub 身份，不新增团队成员、不改写作者，不接管 A/B/C/D 的业务实现。主线继续负责 Root 权限、私有材料、签名、设备部署和最终验收。

## 八个交付动作

1. **核对环境。** 记录真实 OS/UID、磁盘余量、Rust/Cargo1.98.0、Node/Python/Go 版本。按仓库说明核对 Go 与原生音频开发库等前置。可以按现有锁文件准备官方依赖，不能升级依赖、改安全选项或关掉断言来取绿。环境不能安装工具时明确报缺失。
2. **盘点当前检查。** 读取当前 `.github/workflows/rust.yml` 和既有测试入口，建立固定相对路径/参数清单。区分普通无设备组、原生音频组、需要 Root/命名空间/PID1 的专用组；不把匹配0项的命令当作通过，不重复造已有夹具。
3. **写一键运行器。** 提供 `python3 tools/mainline-checks/run.py --group ordinary --output .local/mainline-checks/report.json`；其余明确组用 `--list` 展示。只执行仓库内固定清单中的命令，以参数数组启动，禁止任意 shell/命令/环境注入入口；不以检查名推定某项已成功。
4. **准确记录过程。** 每阶段记录来源完整SHA、是否存在受测代码改动、准确命令、开始/结束、退出码、执行/超时/未运行状态与日志摘要。追踪实际子进程，超时先有界终止和回收；不能因观察超时直接重启同一项。输出目录不得覆盖源码或已有报告；原始日志和环境详情放 `.local/`，公开报告不复制完整环境、凭据或真实数据。
5. **保留失败。** 缺工具/能力标为 `not_run` 并说明，不填通过；测试退出非0标失败，保留原断言，不改产品租约/权限/资源限制。Root 专用项若环境支持，按原脚本原样执行；不支持就保持未运行，不用 Mock 或普通UID流程替代真实Root结果。默认不启动任何业务服务。
6. **验证运行器。** 用合成小进程验证真实退出码、超时/子进程回收、日志超限、缺工具、0项选择、未知组、非干净来源、输出覆盖保护。合成测试只证明运行器，不算固件通过。不要增加外部Python依赖。
7. **实际跑主线。** 在支持的环境执行 fmt、全仓严格Clippy、工作区默认和全部特性两种测试，以及清单里普通网页/工具回归。默认与全部特性有重复测试，分别计数。原生音频按环境能力运行；硬件/ARM运行/真实浏览器/GATT不伪报。不能用之前1374项的旧组合结果代替本次最新SHA。
8. **提交交接。** 提交运行器代码、测试和脱敏报告，通过本人同仓库分支向 main 开 PR。报告包含起始/受测/最终完整SHA（后续仅文档时逐文件说明）、各阶段准确命令/结果、支持/缺失环境、失败最小复现、依赖与来源、未验收项。PR说明这是开发检查辅助，不是发布批准；不要合并自己的PR。

## 运行器的成功标准

- 对同一受测代码和相同环境，检查选择与结果可重复，不能漏掉清单中的可运行检查却给“全部通过”。
- 顶层结果同时显示 passed / failed / not_run 数目；只要有必需检查未运行，整体就不能是 `passed`。
- 整组故障时退出非0，原始输出限量保存且不暴露秘密；不清理别人的缓存/目录、改账户/权限或启动设备服务。
- 工具测试和固件实际运行记录分开，报告可定位到精确源代码；不通过改百分比或降低检查范围宣称交付完成。
